## 三、用户提出的问题（按影响面排序）

### 🔴 1. 成本：超出机构可承受范围（本次反馈的主线）

| 用户表达 | 具体指向 |
|---|---|
| 按一年三千多元的服务器报价，机构预算难以覆盖 | 方案不落地，前面做的都用不上 |
| 明确要求"**其他更省钱的方案**" | 要备选路径，不是要折扣 |
| 追问"如果**把 AI 功能砍掉**，只让网站上线，一年多少钱" | 想知道底线成本 |
| 表示需回机构内部评估投入产出后再定 | 我们要给的是**能拿去开会用的成本说明**，不是技术方案 |
| 🔴 关键优先级表态："如果预算有限，**优先还是知识的检索查询**，AI 功能可以省点预算在上面" | **优先级明确：检索查询 > AI 问答** |

### 🔴 2. 用户主动提出的两条省钱思路

| 用户思路 | 原意 |
|---|---|
| **把"网页"和"知识库"拆开** | 网页服务器只跑页面（便宜）；600 多份资料和 AI 放别处，用链接挂过去。他的原话逻辑是："把 600 多份内容也放进网页服务器，会不会导致服务器价格太高" |
| **用阿里云百炼建知识库 + 问答页挂外链** | 他之前在百炼上建过知识库，知道"按用量收费"；设想：网页只放链接，跳转到百炼的问答页作答，从而把知识库成本从服务器里剥出来 |

> 用户当场承诺提供机构的阿里云账号，供我们核实这条路的真实成本。

### 🟠 3. 功能缺口

| 用户提问 | 需求 |
|---|---|
| "没有注册的**游客，他的权限在哪**？" / "能看看**改权限的那个页面**吗？" | 权限要能在后台自己调，不能写死在代码里 |
| "AI 有 9 次提问，我能看到**这都是谁问的吗**？" / "**主要是看他问了什么内容，以及是谁问的**" | 数据面板要能看到**提问内容 + 提问人身份** |
| "谁注册了一个账号、今天看了一次知识库，**能统计到吗**？" | 单个用户的行为可追踪 |

### 🟠 4. 分类与检索结构

| 用户意见 | 具体要求 |
|---|---|
| **化学品资料只有一层分类，不够用** | 要做成两层：第一层包含「研究报告 / 政策法规 / 各类标准 / **化学品**」，第二层是化学品下属的类别 |
| 第二层要**只在选了化学品时才出现** | 避免筛选项互相干扰 |
| **发布机构不应该只是单选下拉** | 改成**文本搜索**：输"太平洋"，只要发布机构里含这三个字就都列出来——因为机构名写法不统一，穷举必然有遗漏 |

### 🟡 5. 上线交付：用户不清楚自己要做什么

| 用户提问 | 需求 |
|---|---|
| "我想把这个网站让公众能检索到……**从我（甲方）这个角色出发，我应该做什么？最后的交付过程要做什么？**" | 需要一份**甲方视角的上线清单**（要买什么、要备案什么、各要多久） |

### 🟠 6. 对算力被滥用的担心（安全诉求）

用户明确表达顾虑：网站一旦公开，"**担心有人一直去用我那个阿里云的算力**"。
→ 这不是功能需求，是**上线的前置条件**：必须给出可执行的限额策略。

## 六、还没闭环的（已列入下一轮）

1. **成本三选一清单**（用户点名要，且要拿去机构开会）：纯网站上线 / 全量上云 / 拆分方案，各一年多少钱
2. **百炼方案实测**：真实计费方式（按量还是按时长）与月成本——**必须实测，不能估**
3. **防滥用策略**：游客每日次数 + 总量熔断 + 单 IP 频次，形成一条明确承诺
4. **模型切换**：把问答模型切到机构已付费的百炼套餐
5. **甲方上线清单**：域名 / 备案 / 服务器采购 / 时间线

## 七、这次反馈给我们的三点认识

1. **用户最在意的往往不是功能，是"能不能落地"。** 功能做得再全，成本过不了机构那一关，就等于没做。后续方案默认带"最省钱可达版本"。
2. **用户会自己带方案来。** 拆分、百炼外链这两条都是用户提的——我们要做的是**快速验证并给结论**，而不是重新设计一遍。
3. **"能不能自己调"比"做没做"更被看重**：权限、数据、内容都希望能在后台自己控制，而不是每次找开发。
