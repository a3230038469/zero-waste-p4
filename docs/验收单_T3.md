## 一、任务①：UI 缺陷修复（只改一处）

### 改动位置

`frontend/src/views/AdminKnowledgeView.vue` 第 **448** 行：

```diff
 - <el-select v-model="qaEffort" style="width: 100%">
 + <el-select v-model="qaEffort" placeholder="跟随模型" style="width: 100%">
```

### 为什么是这一处

Element Plus 的 `el-select` 未指定 `placeholder` 时回退到组件内置英文默认值 `"Select"`。
该页其余控件都自带中文 `placeholder`（管理口令、跟随引擎默认、按标题筛选、上传表单三处），
唯独「思考强度」这个下拉漏写，所以只有它露英文。

### 实测证据（登录后真实渲染文本）

```json
{
  "now": "当前生效：mimo-v2.6-flash · 知识问答 · 思考强度跟随模型",
  "effort": { "seen": "跟随模型", "phVisible": true, "phText": "跟随模型" },
  "model":  { "seen": "mimo-v2.6-flash" }
}
```

> `phVisible: true` 是**按计算样式**判定的（`getComputedStyle(ph).display !== 'none'`），
> 不是只看 DOM 是否存在 —— Element Plus 会把占位符节点留在 DOM 里靠 CSS 隐藏，
> 只看 `querySelector` 会把「已选中」误判成「占位符中」。这是本次踩过的坑。

### 确认"只改这一处"

| 检查 | 方法 | 结果 |
|---|---|---|
| 全文件 `placeholder` 清单 | grep | 8 处，全部中文；新增 L448 是唯一的「跟随模型」 |
| TODO/FIXME 残留 | grep | 0 |
| 契约/分工冲突 | 对照 `docs/接口约定.md` | 无新增接口、无路由/字段改动，未碰他人文件 |

### [C] `知识问答` 风格偶发「输出上限」——引擎侧问题，非本次改动

同一条 query、同一套设置，**复跑时曾两次**只回一句：

```
Sorry, this answer hit the model's per-response output limit before any text was produced.
```

- HTTP 仍是 **200**、流仍正常收尾（有 `done`、无 `error`），只是模型侧没吐出正文。
- 该提示文案本身**来自引擎**（提示 `raise max_completion_tokens`），不是我们后端生成的兜底。
- 代码侧已做防护：`backend/src/weknora/qa-settings.ts` 的 `knowledge` 风格指令
  写死了「最多 5 点 / 只挑最相关的资料，不要罗列全部」的上限提示，
  但这是**提示词软约束**，不能 100% 保证模型不超。
- 切换 `快速问答` 后同一条 query 立刻恢复正常回答（见 [B]）。

**判定**：`/api/ask` 链路本身正常（200 + SSE + done，三种组合都验过）；
`知识问答` 下偶发空回答属引擎/模型输出上限的既有不稳定性，**非本次 UI 改动引入**，
但写进演示提示：现场若遇到这句话，切「快速问答」即可继续。

### 踩坑：PowerShell 中文 body 编码（重要）

第一次直接 `Invoke-WebRequest -Body '{"query":"什么是零废弃"}'`，**中文被发成乱码**，
引擎回「您的问题似乎是一串问号」。正确做法是先转 UTF-8 **字节数组**再发，
且经 `Start-Job -ArgumentList` 传 string 也可能被改编码，需走 base64：

```powershell
$b64  = [Convert]::ToBase64String([Text.Encoding]::UTF8.GetBytes('{"query":"什么是零废弃"}'))
$body = [Convert]::FromBase64String($b64)
Invoke-WebRequest -Uri ... -Body $body -ContentType "application/json; charset=utf-8"
```

### 另需注意：耗时偏长

`知识问答` + mimo 首问约 25–63 秒；会话A 测到 agnes 首问 100 秒。
任务给的 60 秒超时在这条链路上偏紧 —— 演示若卡住**不代表功能坏了**，
建议演示前预热或切「快速问答」。此项属既有性能特征，非本次改动引入。
