### P1 — 明显影响使用或逻辑不自洽

#### P1-1 游客提问后「今天还能问 N 次」不刷新，且用完不禁用发送

- 现象：第一次提问后，后端已计为 used=1 / remaining=4，页面仍显示「游客今天还能问 5 次」；换新对话后才变成 4。
- 证据：页面内 `fetch('/api/guest/ask-usage')` 返回 `remaining:4`，同屏文案仍是 5。
- 位置：`frontend/src/views/ChatView.vue:173-177`（文案读 `guestUsage`）、`:209`（只在进页时取一次），发送后没有重新拉取。
- 连带问题：发送按钮的 disabled 只判断 `!draft || busy || !activeId || overLimit`（`:1044`），不看 `aiAsk` 开关与剩余次数；次数用完或管理员关闭游客问答时，按钮仍可点，用户白等一轮才被后端拒。
- 建议：每次提问结束后重新拉一次 usage；`remaining<=0` 或 `guestAiOpen=false` 时禁用发送并给明确提示。

#### P1-2 关闭「游客在线预览」后，游客打开任何资料详情都会被直接踢到登录页

- 现象：管理员把游客预览关掉后，游客打开 `/doc/:id`，页面来不及显示标题/机构/年份，就被跳到 `/auth?redirect=...`。
- 证据：实测关闭 preview 后访问详情页，URL 变为 `/auth?redirect=/doc/...`；恢复 preview 后正常。
- 位置：`frontend/src/views/DocDetailView.vue:127`（`canPreview` 只判断体积/PDF，不含权限）、`:252-253`（进页无条件自动预览）；`frontend/src/composables/useDocActions.ts:58-67`（`requireAccess` 未通过就 `router.push('/auth')`）。
- 影响：资料元数据本身是公开的，用户连“这是什么资料”都看不到；应显示元数据 + 把预览区换成登录提示。
- 建议：自动预览前先判断游客权限；无权限时不跳转，只在预览区显示“登录后可在线预览”。

#### P1-3 投稿审核页点「原件」没有任何反应

- 现象：管理员点待审稿件的原件文件名，不打开新标签、不报错、无提示。
- 证据：实测点击后标签页数量不变；同一接口 `GET /api/admin/contributions/:id/file` 用 curl 返回 200 / `application/pdf` / 610 字节，说明接口本身正常。
- 位置：`frontend/src/api/contributions.ts:198-206` 先 `await` 取 blob，再 `window.open(url)`；异步之后再开新窗口会被浏览器弹窗拦截。
- 影响：审核员无法核对原件，只能盲审。
- 建议：点击时先同步开一个空白标签（或改用 `<a download>` / 同页 iframe 预览），拿到 blob 后再填地址。

#### P1-4 「分享（复制对话链接）」别人打不开，但提示「打开就是这条对话」

- 现象：分享按钮复制的 `/chat?c=<id>`，换一个身份/浏览器打开返回 403。
- 证据：权限矩阵中该会话对游客、普通用户、管理员均 403（会话归属校验）；同浏览器原会话正常。
- 位置：`frontend/src/views/ChatView.vue:778-793`，文案明确承诺「打开就是这条对话」。
- 影响：用户会把链接发给同事，对方看到错误页；对“知识分享”定位是硬伤。
- 建议：要么做真正的公开分享（只读快照/分享 token），要么把文案改成「链接仅在本机有效，请截图分享」。

#### P1-5 答不上来时仍挂 3 份不相关引用

- 现象：问「今天北京天气怎么样？」，回答明确说“现有资料中没有找到能回答这个问题的内容”，但回答下方仍显示「3 份资料 ▾」，点开是废动力电池回收、物业垃圾分类、环境危机治本之道，与天气无关。
- 证据：实测回答与引用抽屉同屏。
- 影响：用户会以为“答不上来也有依据”，损害知识库可信度。
- 建议：无答案/兜底回答时清空引用；或只在有实质回答时展示 sources。

#### P1-6 对外“去重后 591 份 / 重复副本 11 组 12 份”与实库不符

- 现象：首页口径弹窗与看板口径写「603 份 / 去重后 591 份 / 重复副本 11 组 12 份」，但当前引擎里 603 份资料按字节大小分组没有任何重复（同大小 0 组）。
- 证据：`GET /api/overview` 返回 `total=603, uniqueTotal=591, duplicateGroups=11, duplicateCopies=12`；遍历 603 条公开列表，按 size 分组无一组重复；按“标题+大小”也无重复。
- 根因：重复标记文件 `backend/data/kb-duplicates.json` 生成于 2026-10-10 本地索引时代，键是 `k-*`；引擎数据源用 UUID，`duplicateOf(uuid)` 永远匹配不上；`overview.ts:169` 仍用这份旧文件的 12 份副本做减法。
- 影响：对外数字口径错误；“另有相同副本 / 查看另一份”功能在引擎模式下永远不会触发。
- 建议：要么按引擎真实数据重新生成重复标记（UUID 键），要么在没有重复时把 uniqueTotal 改为等于 total，并下线“重复副本”口径。

#### P1-7 手机端汉堡菜单不自动收起，会盖住页面按钮

- 现象：手机上先打开汉堡菜单，再点底部「找资料 / 问 AI」跳页，菜单仍展开（高约 150px），直接盖住问答页左上角的「会话」按钮，点不到。
- 证据：实测菜单 `visibility:visible, height:150.8, top:64`；点「会话」报“被 header 里的「首页」遮挡”。
- 位置：`frontend/src/components/SiteNav.vue:190-193` 底部两个 `RouterLink` 没有 `@click="closeMenu"`；菜单项自身有（`:176`）。
- 建议：底部条与所有站内跳转都调用 `closeMenu`，或在路由变化时自动关闭。

#### P1-8 资料级反馈「详细说明（选填）」实际必填

- 现象：详情页反馈弹窗里「详细说明」标注“（选填）”，只勾“文件打不开 / 无法预览下载”不写字点提交，后端返回 400「请写一下反馈内容」。
- 证据：实测弹窗内提交后出现该提示；前端 `FeedbackDialog.vue:93-98` 只对站点级校验，资料级放过空文本；后端 `backend/src/feedback/store.ts:207-208` 一律要求 message。
- 影响：用户按界面提示操作却失败，是典型的“文案与规则打架”。
- 建议：二选一——资料级允许空文本（用问题类型作为内容），或把标签改成“必填”并前端先拦。

## 四、安全与部署口径（不属于功能 bug，但交付前要知道）

1. **埋点可伪造**：`POST /api/track` 无鉴权，且直接采用请求体里的 `userId` / `sessionId` / `ts`（`backend/src/track/store.ts:106-128`）。任何人都能把行为记到任意账号名下，污染看板与使用明细。
2. **游客每日额度可绕过**：额度键由 `X-Forwarded-For + UA + cookie` 组成（`backend/src/guest/ask-usage.ts:109-155`）。实测同一接口换 3 个 XFF 都得到 `remaining:5`；清 cookie 也能换新桶。
3. **上线反向代理后登录/反馈限流会失效**：`auth.ts:340-352`、`feedback.ts:130-141` 用 `req.ip`，但 `index.ts` 没有 `app.set('trust proxy', ...)`；nginx 后所有请求都是 127.0.0.1，5 次/10 分钟会变成全站共享。
4. **Cookie 无 `Secure`**：登录 cookie 与游客设备 cookie 都是（`auth.ts:295-302`、`index.ts:148-151`）；HTTPS 生产环境应补。
5. **网页端可提权**：管理员可把任意用户改成 admin（见 P2-12），无审计日志。
6. **部分错误会带内部原文**：`overview.ts:192-198`（公开接口）、`auth.ts:519-522`、`chat.ts:149-152` 直接把 `err.message` 返回；`errorEnvelopeGuard` 只替换含 URL/堆栈特征的文本。

### 追加：资料详情预览高度塌陷修复（2026-10-23）

- **现象**：打开 15.6MB / 384 页的 PDF 详情页，预览区只剩一条约 28px 高的缝，只看到封面顶部的一条绿边，看起来像“预览坏了”。
- **根因**：T02 修「关闭游客预览」时，在 `.pv-body` 里多套了一层没有高度的 `<div v-else>`，把 `PdfViewer` 的 `height:100%` 高度链打断；`.pdfv-scroll` 的 `clientHeight` 从正常的 474px 塌成 28px。PDF 文件与接口本身正常（接口返回 200 / application/pdf，canvas 有像素）。
- **修复**：把 `<div v-else>` 改为 `<template v-else>`，不产生额外 DOM 节点，恢复高度链（`frontend/src/views/DocDetailView.vue`）。
- **实测**：修复后 `.pv-body` 高 518px、`.pdfv-scroll` 高 474px，封面正常满宽显示（sheet 844px）；lint / typecheck / build 全绿。
- **已知小瑕疵**：15.6MB / 384 页的大文件首次加载时，页面可能先以 160px 小尺寸出现约 1–2 秒，滚动条出现后自动校正为满宽；不影响阅读，后续可再做“加载完成前不显示纸面”的优化。
