## 具体改法

### 问题 1：概览接口去重数字错误（`backend/src/routes/overview.ts`）

- **原**：`duplicateCopies = duplicateCopyCount()` 读取 `kb-duplicates.json`（2026-10-10 旧数据，键是本地索引 `k-*`，引擎数据是 UUID，早已对不上），导致 `uniqueTotal=591` 与实库不符
- **改**：
  - 移除了 `duplicateCopyCount, duplicateGroupCount` 的引用（仅保留 `duplicateOf`，仍用于首页最新收录去重）
  - 在 `buildOverview()` 中新增基于 `size` 字节级分组的计算：
    - 遍历 `listFiles()` 返回的 docs，按 `doc.size` 精确分组
    - `duplicateGroups` = 重复组数（组内份数 > 1 的组数）
    - `duplicateCopies` = Σ(组内数量 - 1)
    - `uniqueTotal = total - duplicateCopies`
  - 当前数据计算结果：`total=603, uniqueTotal=603, duplicateGroups=0, duplicateCopies=0`
- **关键行**：
  - 第 20 行：`import { duplicateOf } from '../data/duplicates.js'`（保留，用于 `latest` 段落的 `duplicateOf(doc.id)`）
  - 第 122-137 行：新增按 size 分组的计算逻辑，替代原 `const duplicateCopies = duplicateCopyCount()`

### 问题 2：看板漏斗百分比>100%且文案不当（`frontend/src/views/AdminStatsView.vue`）

- **原**：
  - `stepRate = (row.value / rows[index-1].value) * 100`——相对上一步计算，步骤非同一链路，百分比可达 >100%
  -  foot-note 写“流失最大的一步（相对上一步只有 X%）”——名不副实
- **改**：
  - 删除了 `stepRate` 字段（`FunnelRow` 接口中移除）
  - `ofPv` 已是相对 PV：`row.value / f.pv * 100`，始终 ≤100%
  - 横条宽度仍用 `ofPv`（`fn-fill`），数值部分改为显示“占 PV X%”
  - foot-note 改为“转化最低的一步：占 PV X%”，去掉“相对上一步”全部字样
- **关键行**：
  - 第 196-201 行：`FunnelRow` 接口，移除了 `stepRate: number | null`
  - 第 214-217 行：`funnelRows` computation，仅保留 `ofPv: (row.value / base) * 100`，删除了 `stepRate` 计算
  - 第 220-224 行：`funnelWorst` computation，现在按 `ofPv` 升序排序，找出占比最低的一步
  - 第 576 行：模板 `<span class="fn-pv zw-num">占 PV {{ row.ofPv.toFixed(0) }}%</span>`，取代了原来的 `fn-rate`
  - 第 580 行：foot-note 改为“转化最低的一步：<b>...</b>（占 PV ...%）”
