## 核心改法说明

### 1. 游客额度不再被 X-Forwarded-For 绕过
- **ask-usage.ts:110-112** `clientIp()` 现在直接用 `req.ip`，由 Express 的 `trust proxy` 机制决定是否信任代理头。
- **index.ts:85-107** 只有显式设置 `TRUST_PROXY` 环境变量时才 `app.set('trust proxy', ...)`：
  - `TRUST_PROXY=true` → `1`
  - `TRUST_PROXY=数字` → 对应数字
  - 其他字符串 → 原样传给 Express
  - 未设置 → **不信任代理**（默认），`req.ip` = 直连客户端 IP
- **注释已写明**：部署到 nginx 后必须设置 `TRUST_PROXY=1`，否则限流会把所有人当成同一个 IP。

### 2. 埋点身份绑定，防伪造 userId
- **track.ts:174-175** 用 `userIdFromRequest(req)` 解析真实登录用户（同 auth.ts/guest/identity.ts 口径）。
- **track.ts:205-208** 对每条通过校验的事件，**覆盖** `event.userId`：
  - 登录用户 → 真实 userId
  - 未登录 → `null`
  - 客户端传来的 `userId` 一律忽略
- **track.ts:207-208** 客户端传来的 `ts` 也一律忽略，落库时间强制用服务端当前时间 `new Date().toISOString()`。
- `sessionId` 保持现状（匿名会话标识）。
- `recordEvent` 调用方（服务端事件）不受影响，仍可显式传 `userId`。

### 3. /api/track 限流
- **track.ts:43-71** 新增简易内存限流：`Map<ip, timestamp[]>`，窗口 1 分钟，上限 240 次。
- **track.ts:154-166** POST 入口最先检查限流，超限返回：
  ```json
  { "success": false, "error": { "code": "RATE_LIMITED", "message": "埋点提交太频繁，请稍后再试" } }
  ```
- 定期清理过期项（`trackRateHits.size >= 5000` 时触发），防止 Map 无限增大。

### 4. Cookie Secure 支持
- **index.ts:173-176** 游客设备 cookie：`COOKIE_SECURE=1` 时追加 `; Secure`
- **auth.ts:297-303** 登录 cookie：`COOKIE_SECURE=1` 时 `secure: true`
- 两处注释均写明：生产环境 HTTPS 时请设置 `COOKIE_SECURE=1`，本地 HTTP 演示不受影响（默认不加）。

### 5. 关闭 X-Powered-By + auth 500 不泄露原文
- **index.ts:96** `app.disable('x-powered-by')` → 响应头不再包含 `X-Powered-By: Express`
- **auth.ts:522-527** 路由级错误兜底：
  - 取 `req.requestId`（由 index.ts 的 requestId 中间件注入）
  - 服务端日志打印：`[auth] 500 requestId=xxx 原始错误信息`
  - 浏览器返回：`{ "error": { "message": "服务器内部错误，请稍后再试" } }`（不含内部细节）

### 6. auth.ts、feedback.ts 已用 req.ip，与新口径一致
- **auth.ts:341** `allowAuthAttempt` 里用 `req.ip ?? 'unknown'`（登录/注册限流）
- **feedback.ts:131** `const ip = req.ip ?? 'unknown'`（反馈限流）
- 两者均直接用 `req.ip`，在 `TRUST_PROXY` 未设置时走直连 IP、设置后走代理后的真实 IP，与 ask-usage 的新口径完全一致。
