## 2. 改法（带行号，指向 `backend/src/feedback/store.ts`）

原问题：`parseFeedback` 第 207 行一律 `if (!message) return [null, '请写一下反馈内容']`，不管 `scope` / `reason`。

修改内容（行号为修改后文件中的行号）：

- **行 209–215**：提前读取 `reason`、`scope`、`docId`（原来在 241–246 重复读取，已删除重复部分）。
- **行 217–227**：
  - `isDocAllowedEmpty = (scope === 'doc' && reason !== '')`
  - `!isDocAllowedEmpty` 时才要求 `message` 非空（站点级保持强制）
  - `message` 超 2000 字时不论 `scope` 一律拒绝（资料级有内容时同受上限约束）
- **行 241–242**：删除重复的 `reasonRaw` / `scopeRaw` 读取，保留 `docId` 读取用于返回对象。

关键逻辑（原文摘录）：
```
const isDocAllowedEmpty = scope === 'doc' && reason !== ''
if (!isDocAllowedEmpty && !message) return [null, '请写一下反馈内容']
if (!isDocAllowedEmpty && message.length > FEEDBACK_MAX_MESSAGE_CHARS) { ... }
if (isDocAllowedEmpty && message.length > FEEDBACK_MAX_MESSAGE_CHARS) { ... }
```

- 当 `scope='doc'` 且 `reason` 非空（已选问题类型：`broken`/`wrong`/`duplicate`/`missing`）→ `message=''` 通过校验，落库为空串，`reason` 保留。
- 当 `scope='site'`（站点级）→ `isDocAllowedEmpty` 始终为 `false`，`message=''` 仍被拒，错误文案仍为 `请写一下反馈内容`。
- `docs/接口约定.md` **未动**（要求优先不改文档，避免并发冲突；文档里 `message` 仍标“是”适用于站点级主路径）。
