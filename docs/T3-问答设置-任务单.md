# T3 任务单：老师后台加「问答设置」（模型选择 / 回答风格 / 思考强度）

## 背景与目标

零废弃知识库（本项目）的 AI 问答链路：前端 → 自建后端 `POST /api/ask` → `backend/src/weknora/index.ts` 的 `askKnowledgeBase()` → 本机 WeKnora 引擎（http://localhost:8080，源码在 `E:/projects/WeKnora`，只读参考）。当前问答模型由引擎知识库配置的 `summary_model_id` 决定（现在是 mimo-v2.6-flash）。

**要给老师后台加一块「问答设置」**，让管理员（不用碰引擎）就能：
1. **选回答模型** —— 从引擎当前可用的 KnowledgeQA 模型列表里选
2. **选回答方式** —— 「快速问答」（简短直答）/「知识问答」（分点、带出处、慢一点），**用提示词模板实现**（在 ask 链路里按所选风格拼装指令）
3. **思考强度** —— 先调研：grep 引擎源码（`E:/projects/WeKnora`）里 knowledge-chat 接口的请求参数，看支不支持 thinking/reasoning/effort 之类参数；**支持就用真参数**，不支持就**不许做假按钮**——在设置卡上放一行说明"由所选模型决定"。参考 WeKnora 自己前端界面的问答选项命名（grep 它的 frontend 源码），风格跟它对齐。

## 技术要求

### 后端（`backend/src/routes/admin.ts` + `backend/src/weknora/`）

- 新增 `GET /api/admin/qa-settings`：返回 `{ currentModelId, currentModelName, models: [{id,name,type,status}], style, updatedAt }`。模型列表从引擎 `GET /api/v1/models` 拉（`X-API-Key`，参考 `weknora/index.ts` 现有写法）。
- 新增 `PUT /api/admin/qa-settings`：body `{ modelId?, style? }`。**校验**：modelId 必须在引擎列表里；style 只能是 `quick | knowledge`。持久化到 **`backend/data/qa-settings.json`**（新文件）。
- **🔴 严禁**：不许直改引擎数据库、不许调 `PUT /api/v1/initialization/config/*`（那个接口会清空知识库分块配置，实测踩过）。
- **生效机制**：`askKnowledgeBase()` 每次请求时读 qa-settings.json —— 若设了 modelId，就在调引擎 `POST /api/v1/knowledge-chat/{sessionId}` 的 body 里加 `model_id`；按 style 在 query 前拼风格指令（quick = "用三五句话简洁回答，直接给要点"；knowledge = "分点详细回答，每个要点注明出自哪份资料"）。流式响应行为不能变。
- 两个新接口都要 `X-Admin-Token` 鉴权（复用 `assertAdmin`），鉴权必须跑在读请求体之前。

### 前端（`frontend/src/views/AdminKnowledgeView.vue`）

- 页面顶部（统计行之下）加一块「**问答设置**」卡片（el-card）：模型下拉（显示引擎返回的模型名，当前项高亮）、回答方式单选（快速问答 / 知识问答，命名参考 WeKnora 自己界面）、保存按钮、保存成功后回显当前生效值。
- 思考强度按调研结果处理（真参数→做控件；没有→放说明文字，禁止放假开关）。
- 载入时 GET qa-settings 回填。
