## 二、五件事拆解

### ① 公众上传（投稿入口）

**要做什么**：给访客一个「我要投稿」入口，提交后进入待审状态。

- **入口位置**：与「反馈」合并在同一个页面（组长建议：上传 + 反馈做成一个页面，两个标签页）。导航栏或页脚给入口。
- **表单字段**：
  - 文件（必填，PDF 优先；单份 ≤ 50MB，与知识库解析能力对齐）
  - 标题（必填）
  - 机构 / 年份 / 类型 / 主题（必填，**下拉选项复用 `GET /api/docs/facets`**，别自己写死）
  - 投稿说明（选填，200 字内）
  - 投稿人信息：已登录则自动带出（姓名/机构/联系方式），未登录可填或强制登录 —— **待拍板，见第七节**
- **提交后**：状态 = `pending`（待审核）。**资料不进书架、不参与检索、不可下载**，只在"我的投稿"里可见。
- **我的投稿**：列表显示自己投过的资料 + 当前状态（待审核 / 已通过 / 已退回）+ 退回理由。

**验收**：投稿成功 → 状态为待审核 → 书架搜不到 → "我的投稿"能看到 → 后台审核队列能看到。

### ② 反馈

**要做什么**：两类反馈，别混在一个框里。

- **对某份资料的反馈**：入口放**详情页**（如「这份资料有问题」）→ 选项：内容有误 / 文件打不开 / 内容重复 / 希望补充相关内容 + 留言
- **对站点的反馈**：入口放**页脚**（如「意见反馈」）→ 分类：功能建议 / 内容建议 / 使用问题 / 其他 + 留言

**技术口径**：提交走 `POST /api/track`，事件名用**现成的** `feedback_submit`（已在白名单里，`backend/src/track/types.ts`）。payload 建议：

```json
{ "event": "feedback_submit", "docId": "k-19", "payload": { "kind": "doc", "reason": "broken", "text": "……" } }
```
站点级反馈 `docId` 省略或传 `null`。

⚠️ **不许新增事件名**。`track/types.ts` 是白名单的唯一真相来源，加事件要跟韶茹说。

**验收**：两类反馈都能提交成功；数据进 `backend/data/track/events.jsonl`；看板 `feedback_submit` 计数增加。

### ③ 审核全链路（**本次最重，也是核心**）

**要做什么**：`投稿 → 待审 → 通过/退回 → 进库 → 告知投稿人`，中间不断链。

**管理端新增「审核队列」页**（沿用 `AdminKnowledgeView.vue` 的"口令门 + 表格 + 搜索 + 分页"风格）：
- 列出所有 `pending` 投稿：投稿人 / 提交时间 / 文件名 / 标题 / 机构 / 年份 / 类型 / 主题
- 支持查看/下载待审文件原件
- 每条两个动作：**通过** / **退回**（退回必填理由）

**「通过」的实现（最容易出岔子的一步，单独说）**：

"通过"不能只改状态 —— 必须**真的把文件送进知识库**，否则书架上永远看不到它。

推荐做法：后端转发给**已有的** `POST /api/admin/knowledge/upload`（带 `X-Admin-Token`），成功后：
1. 状态改 `approved`
2. 记录入库返回的 `docId`
3. 入库失败 → **状态停在 `pending`**，把错误回给管理员（不能假装成功）

> ⚠️ 已知坑：知识库入库有**几秒延迟**，且书架数据与引擎数据是两套（见 `docs/真实数据集接管说明`）。审核通过后请不要立刻断言"书架一定马上有"，测试时留几秒再刷新。

**「退回」**：状态改 `rejected` + 存 `reason`，投稿人在"我的投稿"能看到理由。

**验收**：投一份真 PDF → 后台看到 → 点通过 → 书架上能搜到、详情页能打开 → 投稿人状态变已通过。再投一份 → 点退回 → 同学能看到退回理由、书架始终搜不到。

### ④ 分享（只补两个缺口）

**已有的别动**：详情页「复制分享链接」已实现（`onCopyLink`）。

**要补的**：

- **微信分享卡片**：给「资料详情页」加动态 meta（`og:title` / `og:description` / `og:image`），让资料转到微信群时显示**标题 + 摘要 + 缩略图**。SPA 需要在路由切换时更新（`document.title` + meta 同步），或加一个分享落地路由。**公益传播全在微信群，这条性价比最高。**
- **单份资料二维码**：详情页加「扫码分享」，生成该资料 URL 的二维码（可前端生成，不建议引重依赖；若必须引库先问组长）。

**验收**：资料链接发到微信群有卡片不是干链接；二维码扫出来能直达该资料详情页。

### ⑤ 咨询推荐页（**暂不动手**）

分工里**韶茹负责"资讯推荐展示（可行性分析）"**。"可行性分析"= 先研究能不能做、怎么做，结论出来才有下游页面。**现在动手会白做。**

## 三、接口草案（新增接口必须登记进 `docs/接口约定.md`）

> 命名与鉴权口径照抄现有代码：管理员接口用 `X-Admin-Token`（值 = `ADMIN_STATS_TOKEN`，**fail closed**）；投稿人接口用登录态（JWT，见 `auth.ts`）。

```txt
# 投稿人侧
POST   /api/contributions              提交投稿（multipart，字段同表单一节）
GET    /api/contributions/mine         我的投稿列表（登录态过滤）
       → { success, total, items: [{ id, title, status, reason?, createdAt }] }

# 管理侧（X-Admin-Token）
GET    /api/admin/contributions        审核队列（?status=pending&page=1&pageSize=20）
POST   /api/admin/contributions/:id/approve   通过（内部复用 admin 上传 → 入库）
POST   /api/admin/contributions/:id/reject    退回（body: { reason }）
```

**状态枚举**：`pending` / `approved` / `rejected`（三态，不要加第四个）

**文件与数据落点**：待审文件放 `backend/data/contributions/`（**必须 gitignore**，同 `backend/data/kb/`），投稿元数据落 SQLite（Prisma 新增 `Contribution` 模型；字段名以 schema 为准）。

## 七、需拍板的三件事（开工前问组长/黄老师）

1. **投稿是否必须登录？**
   - 必须登录：数据干净、能追责、能和"登录用户画像"联动（黄老师关心机构/职业）
   - 不登录：门槛低、投稿量大，但无法通知退回理由
   - 我的建议：**必须登录**（也正好让"注册"这件事有实际用处）
2. **投稿文件类型是否限 PDF？** 建议先只收 PDF（引擎解析效果好；Word/Excel 解析质量差）
3. **组长说的"上传 + 反馈做成一个页面"**：确认是一个页面两个标签页（Tab），而不是两个独立页面
