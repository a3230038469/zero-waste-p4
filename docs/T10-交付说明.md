## 七、接口与实现要点速查（给下一个改这块的人）

### 写入解析引擎配置：为什么必须走 `weknora/parser-config.ts`

```
① GET 全量 → ② 覆盖本次要改的字段 → ③ PUT 除密钥外全量 → ④ 再 GET 逐字段比对 → ⑤ 结果如实返回
```

- ③ **少一个字段就可能被清零**（引擎是整体替换；主控实测：提交 1 个字段，18 个被清掉 15 个）
- ③ **密钥不提交 = 保留原值**；⛔ 提交 `***` = 把真密钥覆盖成 `***`（本文件 `buildSubmitBody` 里那行注释别删）
- ⑤ 校验没过**不抛错**：已经写进去了，抛错会让前端显示成「保存失败」，反而误导老师

### 密钥字段怎么判定

按**字段名**（含 `key` / `token` / `secret` / `password`），不靠名单 —— 引擎加字段就自动被认成密钥。
`GET` 的 `configured` 判据是「非空」（实测 `***` = 已保存，不是未配置）。

### `orgLike` 与 `org` 的分工

- `org`（精确多选）：机构**恰好是**这一家，保证「下拉标的数字 == 筛出来的条数」，接口保留未删
- `orgLike`（单值包含）：机构名里**含**这个词，是老库 371 个机构值里 296 个只出现一次的唯一入口
- 两者同时传按 **AND**；`orgLike` 属于「机构」维，算机构筛选项数量时同样不带它
