## 一、目标（一句话）

**把网站问答的"大脑"从"网站自己拼提示词 + 普通知识库问答"换成"引擎里的智能体"，并把智能体的关键配置搬到网页上让老师能改。**

---

## 二、🔴 背景：为什么改（读完再动手）

现状（T3 实现）：

```
网站前端 → POST /api/ask → 后端 askKnowledgeBase()
                              ↓
                        引擎 POST /api/v1/knowledge-chat/{sessionId}
                        body: { query: 风格前缀+问题, summary_model_id, reasoning_effort }
```

**问题**：老师（对话 A 侧）在引擎里配了一个**专用智能体**（`零废弃资料助手`，id 见下方），里面有：
- 一段 777 字的严谨系统提示词（只用库内内容、逐字核对、分条、结尾说依据）
- 模型、温度、长度上限等参数
- 关联的知识库、意图提示词

**但网站问答根本不走这个智能体** —— 智能体的提示词对网站完全无效。
**本任务 = 把这条链路接上，并让老师能在网页上改这些配置。**

## 三、现状事实（已实测确认，不要重新调研）

### 3.1 引擎接口（四条，全部实测过）

| 用途 | 接口 | 实测结果 |
|---|---|---|
| 读智能体 | `GET /api/v1/agents/{id}` | ✅ 200，**config 不裁剪、是数据库的超集** |
| 改智能体 | `PUT /api/v1/agents/{id}` | ✅ 接口存在（真实 id 下 400 = 参数不对，非不存在） |
| 智能体问答 | `POST /api/v1/agent-chat/{sessionId}` | ✅ 正常流式返回 |
| 对照（现用） | `POST /api/v1/knowledge-chat/{sessionId}` | ✅ 现在走这条 |

**鉴权**：请求头 `X-API-Key: <WEKNORA_API_KEY>`（已在 `.env`）
**智能体 id**：`2e7da41a-3b02-473d-b05f-6075fa7cb566`（名称「零废弃资料助手」）

### 3.2 🔴 `agent-chat` 的 SSE 事件格式（2026-10-13 实测，一次完整问答 246KB）

**格式**：标准 SSE，`event:message` + `data:{...}`，每条 data 都有一个 **`response_type`** 字段：

| `response_type` | 条数（实测） | 内容 | 处理建议 |
|---|---|---|---|
| `agent_query` | 1 | 首帧，含 session/message id | 忽略（或作为"已开始"） |
| **`thinking`** | **791** ⚠️ | 思考过程逐字推 | 🔴 **见下方设计决策** |
| `tool_call` | 2 | `Calling tool: query_understand` / `knowledge_search` | 可转成"进度提示"（可选） |
| `tool_result` | 2 | 工具结果（含 `count`/`doc_count`/`duration_ms`） | 可转成"检索到 N 条"（可选） |
| **`answer`** | **117** | 答案逐字推（`content` 字段） | ✅ **核心，必须转发** |
| **`references`** | **1** | **一条事件包含全部引用**（不是分段推） | ✅ **必须转发**（来源卡片） |
| `complete` | 1 | 结束 | ✅ 用它判定结束（**不要靠连接关闭**） |

### 3.3 🔴 两个必须遵守的硬规则（踩了会出大事）

**规则 1：`PUT /agents/{id}` 是「整体替换」，不是「合并」**

源码原文：
```go
existingAgent.Config = agent.Config     // 整体替换，无字段级合并
existingAgent.EnsureDefaults()          // 之后只补一部分默认值
```

而 `EnsureDefaults()` **不补** 这些字段 → 漏传即归零：

| 字段 | 漏传后果 |
|---|---|
| `max_completion_tokens` | 变 0 → 回落到 `config.yaml` 的 **1024** → 长回答会被截断（这是以前修过的 bug） |
| `temperature` | 变 0（**不是** 0.7，因为源码只处理 `<0`）→ 输出变完全确定 |
| `system_prompt` | 变空 → **老师那 777 字提示词全没** |
| `model_id` | 变空 |
| **`fallback_strategy`** | 变空 → 被补成 **`"model"`** → **"库内暂未收录"的固定文案变成模型自由发挥** |

→ **所以必须：`GET 全量 → 表单预填 → 只改表单管的字段 → PUT 完整 config → 回读校验`**

**回读必须校验四项**（值来自当前配置，写死校验）：
1. `max_completion_tokens` = `8192`
2. `system_prompt` 长度 = 777（或与改前一致）
3. `temperature` = `0.3`
4. `fallback_strategy` = `"fixed"`

**规则 2：`kb_selection_mode` 必须保持 `selected`，绝不能设成 `all`**

因为 `all` = **当前租户下全部知识库**，而引擎里现在有 **7 个库**：

| 库 | 份数 |
|---|---|
| 零废弃 | 603 |
| **AI系统学习** | **123** ⚠️ |
| 零废弃-高精度测试 | 35 |
| 课本 | 2 |
| 111 / AI系统学习(0) / 批量导入测试 | 0 |

→ 设成 `all`，问"垃圾分类"会把 **123 份 AI 学习资料**一起拉进检索池。

**将来的"全选"档**（两个库都查）也**必须用"请求传多个库 id"**实现，而不是 `all`：

```json
POST /agent-chat/{sid}
{ "query": "...", "agent_id": "...", "agent_enabled": true,
  "knowledge_base_ids": ["零废弃id", "化学品id"] }   ← 正确
```

（已实测：请求传 `knowledge_base_ids` **会覆盖**智能体配置的库 —— 传老库 → 引用 10/10 来自老库。）

### 3.4 🔴 `thinking` 的设计决策（必须先定）

实测一次问答里 **`thinking` 有 791 条**（占 246KB 的绝大部分）。

**决定：本轮先「不转发」`thinking` 事件**（前端保持现有体验不变），理由：
- 现有前端没有"思考过程"展示区，硬转发会变成一大坨内容
- 转发会显著增加流量（本次 246KB 里绝大部分是它）
- **但后端要计数记录**（`thinking` 条数写进日志），便于排查"为什么慢"

（若老师后续想要"思考过程"，另开任务加"可折叠思考区"。）

**`tool_call` / `tool_result`**：本轮**转成可选的进度提示**（如"正在检索资料…"），**前端默认不显示**，仅保留事件（为以后"检索进度条"留口子）。

## 四、改动清单

### 4.1 后端

**新增 `backend/src/weknora/agent-config.ts`**

```
getAgentConfig(): Promise<AgentConfigView>
  - GET /api/v1/agents/{AGENT_ID}
  - 返回白名单字段（见 4.3），**不要原样把 56 个键丢给前端**

updateAgentConfig(patch: AgentConfigPatch): Promise<{ ok, before, after, checks }>
  - 步骤 1：GET 全量 config（原始对象，一个字不改）
  - 步骤 2：把 patch 里**非空**的字段覆盖上去（**未传的字段保持原值**）
  - 步骤 3：PUT /api/v1/agents/{id}（body 必须是完整 config）
  - 步骤 4：**回读** GET 一次，校验 3.3 那四项
  - 步骤 5：返回 before/after/四项校验结果（任一不过 → 抛错并说明）
```

**新增接口（`backend/src/routes/admin.ts`）**

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| GET | `/api/admin/agent` | `requireAdmin` | 返回智能体关键配置（见 4.3） |
| PUT | `/api/admin/agent` | `requireAdmin` | 改配置，走 `updateAgentConfig`，**回读四项校验不过就报错** |

**改 `backend/src/weknora/index.ts` 的 `askKnowledgeBase()`**

- 新增参数：`agentId`（或从 env 读 `WEKNORA_AGENT_ID`）、`knowledgeBaseIds?`（预留，本轮可为空）
- **走 agent 时**：`POST /api/v1/agent-chat/{sessionId}`，body：
  ```json
  { "query": "<原始问题>", "agent_id": "<id>", "agent_enabled": true }
  ```
  ⚠️ **注意：走 agent 时不要再拼"风格前缀"**（`buildStyledQuery`），提示词由智能体提供。
- **SSE 适配层**（新增，放 `backend/src/weknora/agent-sse.ts`）：
  - 把引擎的 `response_type` 事件**翻译成现有 5 种前端事件**（`ask.ts` 里的既有格式，见 4.4），保证前端不用大改：
    - `answer` → 现有的 `content` 逐字事件
    - `references` → 现有的 `sources` 事件（**注意字段映射**：引擎给 `knowledge_title`/`knowledge_id`/`knowledge_base_id`，现有 `AskSource` 需要 `title`/`id` 等 → 做映射）
    - `complete` → 现有的 `done`
    - `thinking` / `tool_call` / `tool_result` → 丢弃（计数后记日志）
  - **`references` 里没有 `org`/`year`** → 用 `knowledge_id` **从书架已拉的全量列表本地关联**（`listFiles()` 已有），**不要再发请求**
- **兜底**：agent 调用失败（网络/400/401）→ **自动回退** `knowledge-chat`（现有逻辑原样保留），并记日志

**`.env` 新增**
```
WEKNORA_AGENT_ID=2e7da41a-3b02-473d-b05f-6075fa7cb566
```

**`frontend/src/views/AdminKnowledgeView.vue`** 里现有的「问答设置」卡片（约 319–475 行区域）**升级为「智能体设置」卡片**：
