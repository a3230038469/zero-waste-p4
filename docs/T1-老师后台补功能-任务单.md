## 背景（一句话）

这是给公益基金会做的「零废弃知识库」公众网站，给老师用的后台目前只有「看资料列表 + 上传」。这次补齐三件老师天天要用的事。

## 要做的事（三件，按顺序做，每件做完自测）

### ① 删除资料

- **后端**：新增 `DELETE /api/admin/knowledge/:id`
  - 鉴权与现有一致：请求头 `X-Admin-Token`，值 = `backend/.env` 的 `ADMIN_STATS_TOKEN`（**fail closed**：没配就拒绝）
  - 代理引擎：`DELETE {WEKNORA_BASE_URL}/api/v1/knowledge/{id}`，请求头 `X-API-Key`
  - 删除成功后**调用 `invalidateEngineListCache()`**（否则书架最长 60 秒还显示已删的资料）
  - ⚠️ 这个接口**不要**加 `express.raw`（没有请求体）；参照现有 `GET /knowledge` 的写法
  - 引擎返回 404 时回「这份资料已经不在库里了」，不要笼统报 502
- **前端**：后台列表的「删除」按钮由现在的 `notYet('删除')` 改成真的删除
  - 必须二次确认（Element Plus 的 `ElMessageBox.confirm`），确认文案要带上资料标题
  - 成功/失败都要有明确提示；成功后刷新列表
  - ⚠️ **引擎删除有几秒延迟**（列表接口会短暂仍返回它）。删除后请**延迟约 3 秒再刷新**，或刷新两次，避免老师看到"删了没反应"

### ② 看注册用户

- **后端**：新增 `GET /api/admin/users`（同样 `X-Admin-Token` 鉴权）
  - 数据来自本项目自己的 SQLite（Prisma，见 `backend/prisma/schema.prisma` 的 User 模型，字段名以 schema 为准）
  - 返回：`{ success, total, items: [...] }`，每条含 `id / name / org / role / topics / phone / createdAt`
  - ⚠️ **手机号必须脱敏**（中间四位打码，如 `138****8888`）—— 这是对外提供的能力，避免完整手机号外泄
  - 按注册时间倒序
- **前端**：新增页面 `/admin/users`，沿用 `AdminKnowledgeView.vue` 的「口令门 + 表格 + 搜索 + 分页」风格
  - 表格列：姓名 / 机构 / 职业 / 关注议题 / 手机号（脱敏后）/ 注册时间
  - 有搜索框（按姓名或机构筛）
  - 空数据时给一句友好提示，不要白屏

### ③ 后台入口（老师能找到路）

- 现在的痛点是老师**必须手输网址**才能进后台，而且数据看板（`/admin/stats`）和资料管理（`/admin/knowledge`）互相没有链接
- 请在后台页之间加互跳：在 `/admin/knowledge`、`/admin/users`、`/admin/stats` 三个页面顶部加一行「后台导航」，三个入口互相可点，当前页高亮
- ⚠️ **不要把后台链接加进公众导航栏**（顶部那个「首页 / 书架 / 登录注册」是给公众看的）。如果确实想加，先只加一个**不显眼**的入口，并在日志里说明理由

- **后端 / 前端服务现在没在跑**，你自测时自己起：

  - 前端：`cd frontend && npm run dev`（后台）
  - 自测完**请把它们留在运行状态**，主控要接着验收
- 引擎真实接口（今天刚实测过，照这个用，别猜）：
  - 删除单条：`DELETE /api/v1/knowledge/{id}`（header `X-API-Key`）
  - 列表：`GET /api/v1/knowledge-bases/{kbId}/knowledge?page=1&page_size=200`
  - 单条：`GET /api/v1/knowledge/{id}` —— 外面包了一层 `{success,data}`，**要解包**
  - 没有 `/{id}/preview`、`/{id}/download`；取原件走 `POST /api/v1/knowledge-bases/{kbId}/knowledge/batch-download` body `{ids:[id]}`（返回 zip）
