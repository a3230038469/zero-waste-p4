## 二、T10-A：机构改文本式 + 排版

### 2.1 交互（已与主人确认）

- 「机构」**不再用下拉多选**，改成一个**输入框**。
- 输入后**按回车**才筛（不是边输边筛）。
- 筛选语义：**机构名里包含这个关键词**的所有资料，都列出来。
  - 例：输入「太平洋」→ 列出所有「发布机构名称里含『太平洋』」的资料（可能命中多个不同机构）。
- 保留一个「清除」的能力（输入框清空 + 回车 = 不过滤）。

### 2.2 现状（务必先读代码再改）

- 前端 `frontend/src/views/ShelfView.vue`：筛选区是一个 `.toolbar`，里面依次是
  **机构下拉（remote 搜索）→ 所属方向 → 年份 → 主题 → 排序 → 关键词输入框**。
- 后端 `backend/src/routes/docs.ts` 现支持参数：`q / type / org / year / tag / srcTable / sort / page / pageSize / orgSearch`。
  - `org` = 精确匹配机构（多值）；
  - `orgSearch` = **只用于下拉选项的模糊查询**（返回机构名列表），**不是**按机构筛资料。
- 前端 `frontend/src/api/docs.ts` 的 `DocListQuery` 有 `orgs?: string[]`、`srcTables?: string[]`。

### 2.3 后端要加的参数

新增 **`orgLike`**（单值，字符串）：
- 语义：只要资料的机构名 `includes(orgLike)` 就命中（大小写不敏感；前后空白 trim 掉）。
- 与已有 `org`（精确多选）**可共存**；两者同时传时按「同时满足」处理（AND）。
- 🔴 **注意**：机构名里可能有**不换行空格 `\xa0`／全角空格**（实测确实存在，如
  `中国家用电器研究院\xa0生产者责任延伸产业技术创新联盟\xa0…`）。
  → 判断包含关系前，**两侧都要做"Unicode 空白归一"**（把 `\xa0`、`\u3000` 等统一成普通空格或直接去掉），否则用户输普通空格会搜不到。
- 分页与 `total` 口径不变（`orgLike` 生效后的总数）。

### 2.4 前端要改的

1. 机构那一项：`el-select`（multiple/remote）→ 换成 `el-input`，
   - `placeholder`：`发布机构（输完按回车筛选）`
   - `@keyup.enter` 触发筛选；`@clear` 也刷新
   - 输入值进 `route.query.orgLike`，与其它筛选同样支持地址栏回填
2. **排版重排**（主人要求"合理排布"）——改成**两行**：
   - 第一行（常用）：**机构输入框**、**主题**、**类型**
   - 第二行（辅助）：**所属方向**、**年份**、**排序**、**关键词**
   - 保持响应式（窄屏自动换行），不要出现横向滚动条。
3. 「当前筛选」chips 里，机构那一项要能显示 `机构含「太平洋」` 这样的文案，点 × 清掉。
4. 🔴 原机构下拉的 `onOrgSearch / orgSearching / orgOptions` 等逻辑如果不再使用，
   **要删干净**（避免留死代码与 lint 警告）；`api/docs.ts` 里的 `searchOrgs` 若无人用也一并评估（**先确认没有别处引用**）。

#### （2）MinerU / 解析引擎设置

**界面**：
- 显示当前状态：各解析引擎是否可用（`mineru_cloud` / `builtin` / `opendataloader` / `anydoc` / `markitdown` / `paddleocr_vl_cloud` …）

- 「保存」按钮
- 可改的常用项（做成简单表单，不必全 18 个）：
  `mineru_api_key`、`mineru_endpoint`、`mineru_cloud_model`、`mineru_cloud_language`、`mineru_cloud_enable_ocr / _table / _formula`

**后端新增两个接口**（`backend/src/routes/admin.ts`，均走 `requireAdmin`）：

| 接口 | 做什么 |
|---|---|
| `GET /api/admin/parser-config` | 代理引擎 `GET /api/v1/tenants/kv/parser-engine-config`；**返回时把 `mineru_api_key` / `paddleocr_vl_cloud_token` 等密钥字段替换成 `configured: true/false`**，绝不回传真值 |
| `PUT /api/admin/parser-config` | 写配置（流程见下），成功后**回读校验** |

🔴🔴 **写配置的正确流程（主控已实测踩坑，务必照做）**

引擎的 `PUT /api/v1/tenants/kv/parser-engine-config` **不是增量合并**：
**只提交部分字段，未提交的字段会被清空**（主控实测：只提交 `mineru_language`，结果 18 个字段被清掉 15 个）。

因此必须：
```
① GET 全量配置（引擎侧）
② 把用户本次要改的字段覆盖上去；密钥字段：用户没填 → 原样保留"标记"（见下）
③ PUT 回**除密钥外的全部字段**（一个都不能少）
④ 再 GET 一次，逐字段比对：除密钥外，其他字段必须与第 ③ 步提交的一致
⑤ 把校验结果返回给前端（哪一项没过就写哪一项）
```

- **密钥字段怎么处理**：引擎返回的密钥是**脱敏的**（`***`）。
  - 用户**填了新 key** → 提交新值
  - 用户**没填** → **不提交该字段**（实测：不提交时引擎会保留原值）
  - ⛔ 绝对不要"把 GET 回来的 `***` 原样 PUT 回去"（会把真 key 覆盖成 `***`）
- PUT 完要**回读校验**，并把结果如实返回（前端要显示"保存成功 / 哪一项没生效"）。

**测试连接**：代理引擎 `POST /api/v1/system/parser-engines/check`（body 为待测配置），把结果透传给前端。

#### （3）一键自检

`POST /api/admin/selfcheck` —— 一次返回四项结果（每项含 `ok` + 一句人话说明 + 耗时）：

| 检查项 | 怎么测 |
|---|---|
| **知识库引擎** | `GET {WEKNORA_BASE_URL}/api/v1/system/parser-engines`（带 X-API-Key）；超时 5s |
| **数据库** | 查本地 SQLite（Prisma 一次 `user.count()` 之类） |
| **向量服务** | `GET http://127.0.0.1:11434/api/version`（Ollama；地址可读 `.env`，没有则用默认）；超时 3s |
| **MinerU 云解析** | 取上一步引擎返回的 `parser-engines` 里 `mineru_cloud.Available` |

前端展示：四个带颜色的小卡片（绿 = 通过 / 红 = 失败），失败的给出**一句人话**（如"向量服务没启动：请运行 …"），**不要甩英文报错原文**。

🔴 自检**必须容错**：任何一项失败都不能让整个接口 500，要返回 `{ok:false, message}`。
