### 问答设置（`GET /api/admin/qa-settings` / `PUT /api/admin/qa-settings`）

老师后台的「问答设置」卡片。**只改我们自己的设置**，不碰引擎数据库、不调 `PUT /api/v1/initialization/config/*`。

```json
{
  "success": true,
  "currentModelId": "56f7ae2d-…",
  "currentModelName": "mimo-v2.6-flash",
  "models": [
    { "id": "56f7ae2d-…", "name": "mimo-v2.6-flash", "type": "KnowledgeQA", "status": "active" }
  ],
  "style": "knowledge",
  "styles":   [{ "value": "quick", "label": "快速问答", "hint": "…" }],
  "reasoningEffort": "auto",
  "efforts":  [{ "value": "off", "label": "关闭" }, { "value": "auto", "label": "自动" }],
  "modelsError": "",
  "updatedAt": "2026-10-10T02:00:00.000Z"
}
```

| 字段 | 取值 | 说明 |
|---|---|---|
| `modelId` | 模型 id 字符串，**空串 = 跟引擎默认** | `PUT` 时必须在引擎 `KnowledgeQA` 列表里，否则 400 `MODEL_NOT_AVAILABLE` |
| `style` | `quick` \| `knowledge` | 只能这两个值，其他值 400 `INVALID_STYLE`。默认 `knowledge` |
| `reasoningEffort` | `off\|auto\|minimal\|low\|medium\|high\|xhigh\|max`，**空串 = 交给引擎默认** | 引擎原生参数，非空时非法值 400 `INVALID_REASONING_EFFORT` |
| `modelsError` | 字符串 | 引擎取不到模型列表时的原因；此时 `models` 为空数组，**接口仍 200**，已保存的设置照常返回 |

- 三个字段在 `PUT` 里都是**可选**（只传要改的）；传空串表示「清掉这一项、跟引擎默认走」
- 持久化在 `backend/data/qa-settings.json`（运行时文件，已 gitignore）
- **`models` 由后端按 `type === 'KnowledgeQA'` 过滤**：引擎 `GET /api/v1/models` 不支持 `?type=` 参数（WeKnora 前端那个 filter 是纯客户端的）

**生效机制（`POST /api/ask` 链路，`weknora/index.ts`）**：每次请求现读设置文件

| 设置 | 注入引擎请求体的字段 |
|---|---|
| `modelId` 非空 | `summary_model_id` |
| `reasoningEffort` 非空 | `reasoning_effort` |
| `style` | 在 `query` 文本前拼一段风格指令（`quick` = 简洁给要点；`knowledge` = 分点并注明出处） |

> ⚠️ **T7 起**：走智能体链路时，上表三项**一律不生效** —— `POST /api/ask` 会改打
> `agent-chat`，且**不拼风格前缀、不下发 `summary_model_id` / `reasoning_effort`**
> （提示词、模型、长度上限、兜底文案全部听智能体的）。智能体没走成时自动回退兜底链路，
> 上表才恢复生效。接口本身（`/qa-settings`）**保留未删**，只是页面上不再提供这三个控件。

> ⚠️ **不是 `model_id`**。引擎 `CreateKnowledgeQARequest` 里没有 `model_id`，传了会被 json 绑定**静默忽略**（仍返回 200 但没换模型）；真正的按请求换模型字段是 `summary_model_id`，且必须是 `KnowledgeQA` 类型，否则引擎也会静默回退到默认模型 —— 所以校验必须在我们这层做。

### 智能体设置（T7：`GET /api/admin/agent` / `PUT /api/admin/agent`）

老师后台里从「问答设置」升级来的那张卡片。**它改的不是我们的设置文件，是引擎里那个智能体本体** ——
网站的提示词、回答模型、长度上限、兜底文案现在都在智能体里，老师在这改一行，问答立刻换一套脑子。

| 与 `/qa-settings` 的差别 | `/qa-settings`（T3） | `/agent`（T7） |
|---|---|---|
| 改什么 | 我们自己的 `qa-settings.json` | **引擎数据库里的智能体** |
| 模型字段 | `summary_model_id`（按请求下发） | `model_id`（智能体自带，**走智能体时不再按请求下发**） |
| 回答方式 | 在 query 前拼风格指令 | **已下线** —— 提示词由 `system_prompt` 统一提供 |
| 思考强度 | `reasoning_effort`（按请求下发） | **本页不提供** —— 由智能体在引擎侧的配置决定 |

| 项 | 约定 |
|---|---|
| 字段白名单 | **只碰这 6 个**：`system_prompt` / `model_id` / `temperature` / `max_completion_tokens` / `fallback_strategy` / `fallback_response`。引擎那份 config 共 **56 个键**，其余一律原样透传 |
| 提交白名单之外 | 后端**直接丢弃**（`kb_selection_mode` / `knowledge_bases` / `agent_mode` / `intent_prompts` 等提交了也没用） |
| 🔴 空串 = 「不改」 | **不是清空**。整体替换下传空串等于抹掉那 777 字提示词，所以空串会被忽略并在 `ignored` 里如实回报 |
| `model_id` | 必须在引擎 `KnowledgeQA` 模型列表里，否则 400 `MODEL_NOT_AVAILABLE`（引擎对不存在的 `model_id` 是**静默回退**，不校验老师会以为没生效） |
| `temperature` | 0–2（页面控件限 0–1），否则 400 `INVALID_AGENT_FIELD` |
| `max_completion_tokens` | 正整数 |
| `fallback_strategy` | `fixed` \| `model` |

#### 🔴 为什么这个接口必须「读全量 → 合并 → 整份写回」

引擎源码（`internal/application/service/custom_agent.go`）：

```go
existingAgent.Config = agent.Config     // 整体替换，无字段级合并
existingAgent.EnsureDefaults()          // 之后只补一部分默认值
```

而 `EnsureDefaults()` **不补**下面这些 → 漏传即归零：

| 字段 | 漏传后果 |
|---|---|
| `max_completion_tokens` | 变 0 → 回落到 `config.yaml` 的 1024 → 长回答被截断（以前修过的 bug） |
| `temperature` | 变 0（**不是** 0.7，源码只处理 `<0`） |
| `system_prompt` | 变空 → 那 777 字提示词全没 |
| `model_id` | 变空 |
| `fallback_strategy` | 变空 → 被补成 `"model"` →「库内暂未收录」的固定文案失效 |

所以 `weknora/agent-config.ts` 的写入路径被写死成五步，**没有第二条路**：

```
GET 全量 config → 只覆盖 patch 里的非空字段 → PUT 完整 config → 回读 GET 一次 → 校验四项
```

**回读必须校验四项**（目标字段名写死，期望值来自本次要写的那份 config）：
`max_completion_tokens` = 8192、`system_prompt` 长度 = 777（与改前一致）、`temperature` = 0.3、`fallback_strategy` = `"fixed"`。
任一不过 → **抛错**并在 message 里写清「哪一项期望什么、实际什么」，接口回 502 `AGENT_VERIFY_FAILED`。

#### 🔴 `kb_selection_mode` 恒为 `selected`

`all` = **当前租户下全部知识库**。引擎里现在有 7 个库，其中「AI系统学习」有 **123 份** ——
设成 `all`，问「垃圾分类」会把不相干的资料一起拉进检索池。

- 写入**前**：若当前值是 `all` → **拒绝写入**（409 `AGENT_KB_MODE_FORBIDDEN`），本接口**不会替老师改这个口径**；
  其它非 `selected` 的异常值（空串等）会被拉回 `selected`。
- 回读**后**：作为第五项校验一并核对。
- 将来的「全选」档也必须用**请求传多个库 id**（`agent-chat` 的 `knowledge_base_ids`，实测会**覆盖**智能体配置的库），**不能**改成 `all`。

#### PUT 的请求体形状（2026-10-13 实测逼出来的）

```json
{ "name": "…", "description": "…", "avatar": "", "config": { …完整 56 键… } }
```

引擎的 Go 结构体是 `UpdateAgentRequest{name, description, avatar, config}`。
用类型错误探测法确认（发 `{"config":456,"name":123}` 必被绑定拒绝、**不会写库**）：

```
{"error":{"details":"json: cannot unmarshal number into Go struct field
 UpdateAgentRequest.config of type types.CustomAgentConfig","message":"Invalid request parameters"}}
```

`is_builtin` / `enabled` / `tenant_id` 会被**静默忽略**，不要往 body 里塞。

#### 错误码

| 状态码 | code | 含义 |
|---|---|---|
| 403 | `ADMIN_NOT_CONFIGURED` / `ADMIN_FORBIDDEN` | 口令没配 / 口令不对（fail closed） |
| 400 | `INVALID_AGENT_FIELD` | 字段类型或取值不合法 |
| 400 | `MODEL_NOT_AVAILABLE` | 选的模型在引擎里不存在 |
| 404 | `AGENT_NOT_FOUND` | 引擎里没有这个智能体 |
| 409 | `AGENT_KB_MODE_FORBIDDEN` | 智能体的知识库范围是 `all`，拒绝写入 |
| 502 | `ENGINE_UNAUTHORIZED` | 引擎拒绝：API Key 无效或无权限 |
| 502 | `ENGINE_REJECTED_UPDATE` | 引擎拒收这次保存，**配置没有改动** |
| 502 | `AGENT_VERIFY_FAILED` | 已写入但回读校验没过，message 里写明是哪一项 |
| 503 | `ENGINE_NOT_CONFIGURED` / `AGENT_NOT_CONFIGURED` | 缺 `WEKNORA_API_KEY` / `WEKNORA_AGENT_ID` |

### 解析引擎设置（T10：`/api/admin/parser-config` 三条 + `/api/admin/selfcheck`）

老师后台「设置」页的第 2、3 块。它改的是**引擎里那份解析引擎配置**（上传的 PDF/PDF 靠它转文字），
**不是**我们的设置文件 —— 与 `/agent` 同性质：写引擎本体。

#### 🔴 为什么写入必须是「读全量 → 合并 → 整份写回 → 回读校验」

引擎 `PUT /api/v1/tenants/kv/parser-engine-config` 是**整体替换**，不是字段级合并。
主控 2026-10-14 实测：**只提交 `mineru_language` 一个字段，18 个字段被清掉 15 个。**

所以 `weknora/parser-config.ts` 把写入路径写死成五步，**没有第二条路**：

```
① GET 全量配置（引擎侧，一个字不改）
② 把本次要改的字段覆盖上去；密钥字段：用户没填 → 不提交该字段
③ PUT 除密钥外的全部字段（一个都不能少）
④ 再 GET 一次，逐字段比对：除密钥外，其余字段必须与第 ③ 步提交的一致
⑤ 校验结果原样返回前端（哪一项没过就写哪一项）
```

| 引擎实测的 18 个字段 | 类型 | 页面可改 |
|---|---|---|
| `mineru_api_key` | 文本（**密钥**） | ✅（留空 = 不改） |

> 字段名单靠 `GET` 现读，代码里只按**类型**校验提交值。

#### 🔴 密钥字段的三条铁律（主控实测踩过坑）

1. 引擎 `GET` 回来的密钥是**脱敏的** `***`；
2. 用户**填了新 key** → 提交新值；用户**没填** → **不提交该字段**（实测：不提交时引擎保留原值）；
3. ⛔ **绝不**把 `GET` 回来的 `***` 原样 `PUT` 回去 —— 那会把真密钥覆盖成 `***`。

后端按**字段名**判定密钥（含 `key` / `token` / `secret` / `password`），不靠名单。
当前引擎 18 个字段里只有 `mineru_api_key` 命中（`paddleocr_vl_cloud_token` 在实测的版本里**不存在**，
所以它的「未配置」只会体现在 `parser-engines` 的 `UnavailableReason` 上）。

|---|---|---|

| 502 | `ENGINE_STILL_DELETING` | 删完 15 秒旧记录还没退干净，**旧记录仍在库里**，请过十几秒再点一次 |

> ⚠️ **2026-10-12 真机实测出来的三条引擎行为，改这个接口前务必知道**（都写进了 `routes/admin.ts` 的注释）：
>
> 1. **引擎的删除是异步的**：DELETE 只把记录标成 `deleting`，真正消失还有几秒。
>    这期间把同一个文件传回去会被判 `duplicate_file`(409)。所以「删完立刻传」必须
>    中间等一下（旧记录 GET 不到、或 `parse_status` 已是 `deleting` 才算退场）。
> 2. **重复文件按内容 hash 判，不是按文件名**：同名不同内容传得进去，改名同内容会 409。
>    所以别想着「改个文件名绕过去」。
> 3. **`custom_metadata` 的值只能是字符串 / 数字 / 布尔**：数组、对象会被引擎拒。
>    补回前会逐项过滤（`sanitizeCustomMeta`），宁可少写一项也不让整份 PUT 失败。

### 投稿与审核（B09：`/api/contributions` + `/api/admin/contributions`）

访客投稿闭环的六个接口。**口径（2026-10-11 三件拍板）**：投稿必须登录、只收 PDF、
投稿+反馈一个页面两个 Tab。三态状态机 `pending → approved / rejected`，**不要加第四态**。

**提交投稿**：

```
POST /api/contributions?title=…&org=…&year=…&type=…&tags=…&note=…
请求头：Authorization: Bearer <token>（或 cookie zwp_token）
        X-File-Name: <URL 编码的文件名>，必须以 .pdf 结尾
请求体：PDF 原始二进制（application/octet-stream，单份 ≤ 50MB）
→ 201 { success, message, data: { id, status: "pending", … } }
```

**审核**（管理侧都要 `X-Admin-Token`）：

```
GET  /api/admin/contributions?status=pending&page=1&pageSize=20&keyword=焚烧
     → { success, total, page, pageSize, counts: {pending, approved, rejected}, items[] }
GET  /api/admin/contributions/:id/file        → 内联 PDF 流
POST /api/admin/contributions/:id/approve     → 真入库，成功才改 approved
POST /api/admin/contributions/:id/reject      body { "reason": "…理由必填…" }
```

> `keyword` 在 `status` 过滤之后再做一次模糊匹配，命中范围：标题 / 机构 / 文件名 / 投稿人姓名 / 投稿人机构。
> 前端只在回车或点「搜索」时请求，不逐字打后端。

**「我的投稿」**：`GET /api/contributions/mine`（登录态过滤），返回本人全部投稿，
含 `status` 与 `reason`（退回理由）——这是投稿人了解审核结果的唯一通路。

| 状态码 | code | 含义 |
|---|---|---|
| 400 | `MISSING_TITLE` / `MISSING_META` / `BAD_FILE_TYPE` / `EMPTY_FILE` | 标题没填 / 四维没选齐 / 不是 PDF / 文件为空 |
| 400 | `MISSING_REASON` | 退回没写理由（至少 2 个字） |
| 401 | `AUTH_REQUIRED` / `USER_NOT_FOUND` | 未登录 / 登录用户已不存在 |
| 403 | `ADMIN_NOT_CONFIGURED` / `ADMIN_FORBIDDEN` | 口令没配 / 口令不对（与老师后台同款 fail closed） |
| 404 | `NOT_FOUND` | 投稿编号不存在 |
| 409 | `ALREADY_REVIEWED` | 这条投稿已经审过了（防止重复审核） |
| 410 | `FILE_GONE` | 待审原件已不在服务器上 |
| 413 | `FILE_TOO_LARGE` | 超过 50MB |
| 502 | `INGEST_FAILED` | **入库失败，状态仍是 pending**（绝不假装通过）；`message` 带引擎侧原因 |

> ⚠️ **数据落点与「通过」的实现**（改这两处前必读，详见 `routes/contributions.ts` 注释）：
>
> 1. 投稿元数据落 `backend/data/contributions/index.json`、原件落 `…/files/`
>    （**已 gitignore**，含投稿人个人信息，绝不能进仓库）。**没有**用 Prisma ——
>    `schema.prisma` 是 B02 的文件，硬约束「不改别人的文件」；字段名与任务书里的
>    Prisma 草案对齐，要并库照字段搬即可。
> 2. 「通过」**不直接调引擎**，而是转发给已有的「管理·上传资料」（带 `X-Admin-Token`），
>    复用它的入库、标签写入、缓存失效三步。所以引擎连不上 / 拒收时，状态**必须**停在
>    pending 并把原因回给管理员。
> 3. 投稿人侧的 JWT 校验与 `auth.ts` 同口径（Bearer 优先、cookie 兜底、密钥 `JWT_SECRET`），
>    但在该文件内自带一份 —— `auth.ts` 没有导出这个函数，而硬约束是不改别人的文件。

**多选传法（2026-10-07 定稿——老师要求书架页「机构/年份/主题」支持多选）：**

同一参数重复出现即多选，例：

```
GET /api/docs?type=政策法规&org=零萌公益&org=自然之友&year=2023&year=2024&tag=垃圾分类&tag=堆肥
```

- 同一维度内是**或**：机构 = 零萌公益 或 自然之友
- 不同维度之间是**且**：在机构基础上再叠加年份、主题

#### 【T10】机构改文本式：`orgLike`（单值包含匹配）

`org`（精确多选）与 `orgLike`（包含匹配）是**两套语义**，同时传按 AND 处理：

```
GET /api/docs?orgLike=太平洋     → 机构名里含「太平洋」的全部资料（可能命中多家机构）
GET /api/docs?org=零萌公益&orgLike=环保 → 机构恰好是零萌公益，且机构名含「环保」
```

| 项 | 约定 |
|---|---|
| 比对方式 | **包含**（`includes`），不是全等。输入「太平洋」会同时命中「太平洋 XX 基金会」「XX 太平洋 中心」等 |
| 大小写 | 不敏感（老库有 `UNEP` / `WWF` 这类大写写法，输 `unep` 也要命中） |
| 🔴 空白归一 | 两侧都做 Unicode 空白归一（`\xa0` 不换行空格 / `\u3000` 全角空格 → 普通空格）。老库实测确有机构名带 `\xa0`（`中国家用电器研究院\xa0生产者责任延伸…`），不归一则用户敲普通空格搜不到 |
| 归属维度 | 属于「机构」这一维，所以 `GET /api/docs/facets` 算**机构**的筛选项数量时同样不带它（计数与实际结果一致） |
| 分页口径 | 不变：`total` 是 `orgLike` 生效后的总数 |
| 与前端的关系 | 书架页「机构」已从下拉多选改成**输入框 + 回车**（输完才筛，不是边输边筛）。原来的 `?orgSearch=`（只用于机构下拉选项的模糊查询）**前端已不再调用，接口保留未删** |

> 为什么改：老库 371 个机构值里 **296 个只出现 1 次**，下拉只列得出 42 项；
> 想找「太平洋」这类**出现在长联合发文串里**的机构，下拉根本点不到。
> 文本式一次输入就能把含该词的资料全列出来。
- `GET /api/docs/facets` 接受**与列表相同的筛选参数**，用于各维度计数时排除自身维度的选择（保证计数与实际筛选结果一致）
- **前端注意**：axios 默认把数组序列化成 `org[]=a&org[]=b`，必须配置 `paramsSerializer`（`arrayFormat: 'repeat'`）才能发出 `org=a&org=b`
- **后端注意**：Express 里单值时 `req.query.org` 是 string，多值时是 string[]，**必须归一化成数组**再处理，别只按数组写

**响应格式（必须一致）**

```json
{
  "total": 476,
  "page": 1,
  "pageSize": 20,
  "zeroResult": false,
  "items": [
    {
      "id": "k-1",
      "title": "咖啡渣堆肥指南",
      "org": "零萌公益",
      "year": 2023,
      "type": "案例工具",
      "tags": ["厨余处理", "垃圾分类"],
      "size": 1408332
    }
  ]
}
```

> **`zeroResult: true`** 表示搜索无结果，前端据此显示"没有匹配的资料 + 试试问 AI"。

### 筛选项（`GET /api/docs/facets`）

```json
{
  "types":  [{ "value": "政策法规", "count": 120 }],
  "orgs":   [{ "value": "零萌公益", "count": 18 }],
  "years":  [{ "value": "2023", "count": 42 }],
  "tags":   [{ "value": "垃圾分类", "count": 120 }],
  "srcTables": [
    { "value": "知识查询（零废弃）", "count": 480, "label": "零废弃" },
    { "value": "知识查询（化学品）", "count": 123, "label": "化学品与健康" }
  ]
}
```

> **重要**：下拉里显示的数量，必须和实际筛出来的条数**完全一致**。
> 本接口接受与列表**相同的筛选参数**（type/org/year/tag/srcTable/q），每维度的计数要**排除该维度自身的已选项**（否则点选后计数会越点越少）。
>
> 实现语义（后端已按此实现并实测）：算某个维度的数量时**不带该维度自己的条件、但带上其他已选条件**。
> 因此前端可以把当前筛选原样带上（如 `/api/docs/facets?type=政策法规`），
> 数量会随筛选实时收敛，且「下拉标的数字」和「选中后筛出来的条数」在任何叠加状态下都相等。
>
> **⚠️ 2026-10-10 追加：`years` 不含 `"0"`。**
> `year = 0` 是「台账未填年份」的内部表示（真实数据里有 1 份），它不是「公元 0 年」。
> 若列进下拉，用户会看到一个毫无意义的「0」选项。后端已在 `years` 里把它过滤掉；
> 前端在列表/详情上遇到 `year === 0` 时按「年份不详」显示。

#### 【T8】机构维度：过滤 + 搜索 + 别名归一（2026-10-13）

老库 603 份实测：机构原始值 **370 个**，其中 295 个只对应 1 份资料，**全列等于废掉**。
所以 `orgs` 的返回口径分两种：

| 请求 | `orgs[]` 里是什么 | 条数 |
|---|---|---|
| 不带 `orgSearch` | 只列**单机构**且出现 **≥2 次**的（别名归一后合并）**＋一条「联合发文」汇总** | 实测 **42 项** |
| 带 `orgSearch=关键字` | **全部**机构值里模糊命中关键字的（含低频、含联合发文长串） | 上限 **20 条** |

| 项 | 约定 |
|---|---|
| `orgSearch` | 【T8 新增查询参数】大小写不敏感的包含匹配。**只在机构这一维生效**，其余维度照常返回，响应形状与不带它时完全一致 |
| 别名归一 | `UNEP`→`联合国环境规划署`、`WWF`→`世界自然基金会`、`国家发改委`/`发改委`/`发展改革委`/`国家发展改革委`→`国家发展和改革委员会`、`市场监管总局`→`国家市场监督管理总局`。**只归一显示与筛选口径，不改任何数据** |
| 🔴 不合并 | `环境保护部` / `生态环境部`：2018 年机构改名，历史文件用旧名是事实，合并反而失真 |
| 联合发文 | 一个 org 值里有多家机构（老库 **266 份 / 44%**）。分隔符是**五种**：`、` `,`（半角） `+` 空格（含 `\xa0` 不换行空格、换行）。长串**不单独列**，搜索命中时用 `label` 显示成 `A + B 等N家` |
| 联合发文的键 | 逐段别名归一后用 ` + ` 拼回来（`财政部 + 国家发展和改革委员会 + 国家能源局`），**幂等** —— 所以同一个组合在数据里用顿号/空格/换行写的几种变体会落成同一个键，不会并排出现三条近乎一样的长串。`A / B` 里被切出来的纯标点碎片（`/`）会被丢掉 |
| 联合发文汇总项 | `value` = `__joint__`（前端原样回传即可），`label` = `联合发文（多家机构联合署名）`，`count` = 多家机构署名的份数。用途：这 266 份原本在下拉里**没有任何入口** |
| `label` | 【T8 新增可选字段】展示名，**只影响显示**；提交筛选仍传 `value`。不出现时前端按 `value` 显示 |
| 搜索范围 | 单机构按「主名 + 全部别名写法」匹配；联合发文按**其中每一家机构**匹配（输入「发改委」能同时命中「国家发展和改革委员会」和含它的联合署名组合），命中后显示短标签 |
| 筛选口径 | 单机构项按「归一键**恰好相等**」筛；`__joint__` 筛「org 里含 ≥2 家机构」。这样**下拉标的数字 == 选中后筛出来的条数**（上面那条硬要求） |

> ⚠️ **已知取舍**：给「联合发文」按单家机构拆开计数的话，下拉会从 42 项涨到 **150+ 项**，
> 与验收「≤60 项」冲突；而且计数口径一改，数字与筛选结果就不再严格相等。
> 所以本轮的取舍是：**下拉只列单机构高频值 + 一条联合发文汇总**，
> 其余（含「国家市场监督管理总局、国家标准化管理委员会」这种 28 份的大联合串）靠**搜索框**点到。
> 是否改口径需业务方拍板。

#### 【T8】所属方向 `srcTables`

数据源：引擎 `custom_metadata.srcTable`。老库实测只有两个值（`知识查询（零废弃）` 480 份、`知识查询（化学品）` 123 份）。

  而不是摆一个筛不中的假选项
- 默认**不过滤**（空数组即不加条件）

### 流式问答（`POST /api/ask`）

给 B07 问答窗口用：前端把问题发给**自建后端**，后端代理引擎并以 SSE 逐字回吐。

```
POST /api/ask
Content-Type: application/json

{ "query": "厨余垃圾怎么堆肥？" }
```

成功返回 `200` + `Content-Type: text/event-stream; charset=utf-8`，每行一条事件：

```
data: {"type":"answer","content":"家庭堆肥"}
data: {"type":"answer","content":"可分三步……"}
data: {"type":"sources","items":[{"name":"382-厨余垃圾全生命低碳管理综述.pdf","url":"/doc/5085edc8-…"}]}
data: {"type":"done","content":""}
```

| `type` | 含义 | 前端该怎么做 |
|---|---|---|
| `answer` | 正文分片 | 追加到气泡里（**逐字渲染，不要等 done**） |
| `sources` | **T4 新增**：回答引用的资料清单（**无 `content`，只有 `items`**） | 渲染成气泡底部的来源卡片，点 `url` 跳详情页 |
| `thinking` | 思考过程（默认不透，`includeThinking: true` 才给） | 可折叠展示，不展示也不影响 |
| `done` | 正常收尾 | 停止 loading，把气泡收尾 |
| `error` | 出错收尾 | 显示 `content` 里的提示；`AI 暂时不可用` 也走这里 |

**`sources` 事件细则（2026-10-12 补）**

```json
{ "type": "sources", "items": [{ "name": "382-厨余垃圾全生命低碳管理综述.pdf", "url": "/doc/<id>" }] }
```

| 项 | 约定 |
|---|---|
| 时机 | 在 **`done` 之前**发（前端先拿到卡片再收尾，气泡不会「先结束、后冒卡片」）；每条流**最多一条** |
| 字段 | `name` = 资料名，`url` = 站内详情页 `/doc/<id>`（**前端拿它 `router.push` 即可**，预览/下载按钮在详情页） |
| 条数 | 最多 **5** 条，按回答里首次引用的先后排序，同一资料已去重 |
| 空数组 | **不发这个事件**（没有可点的来源就当没这回事，不发空壳） |
| 匹配不上的引用 | **直接跳过**，绝不返回点进去 404 的死链 |
| 旧前端 | 不认识 `sources` 会忽略它，**老调用方行为不变** |

> ⚠️ **引用标记格式：引擎实际输出不稳定，实测有三种，全都要认**（见 `weknora/index.ts` 的 `CITATION_*`）：
> `<kb doc="…"/>`（WeKnora 原生）、`【资料名：xxx.pdf】`（风格提示词诱导）、`【xxx】`（模型只给标题）。
> 同一个问题连问两次就可能给出两种 —— 只认一种会出现「来源卡片时有时无」。
> 文件名与资料标题的对应靠 `listFiles()` 的清单做**归一化匹配**（去扩展名、去空白、
> 拆掉 `序号-机构-标题-标题` 这种重复尾巴），并容忍模型在输出上限处把文件名截断。

- 流**已开始后**的报错只能以 `error` 事件收尾，HTTP 状态码不再变；流开始前的错误用普通 JSON：`{ "type":"error", "content":"……" }`
- **前端不能用 axios 读流**（axios 不吐增量），用原生 `fetch` + `response.body.getReader()`；现成封装见 `frontend/src/api/ask.ts`
- 问题必填，**上限 500 字**，超了返回 400
- 引擎密钥未到位时：流开始前返回 `503`，body 是 `{"type":"error","content":"AI 暂时不可用"}` —— 与 `POST /api/embed/token` 的降级口径一致
- 🔴 **T11 起**：游客能不能问改由「游客权限」开关决定（见本文第二节「游客权限」）——
  `aiAsk` 关闭 → `403 GUEST_ASK_CLOSED`；`aiAskDailyLimit` 用满 → `403 GUEST_ASK_LIMIT_REACHED`。
  环境变量 `REQUIRE_LOGIN_FOR_ASK` **保留但降级为 `aiAsk` 的初始默认值**。
  ⚠️ 这两条判定**只在开流前**做；事件格式（`sources/answer/done/error/…`）一个都没改

#### 建会话

```
POST /api/chat/conversations
{ "title": "可选，不传则「新对话」" }
```

```json
{ "success": true,
  "conversation": { "id": "7757…", "title": "新对话", "engineReady": true,
                    "createdAt": "…", "updatedAt": "…", "messageCount": 0, "lastMessage": "" } }
```

- 建库里的会话时**顺带在引擎建 session**，把 `engineSessionId` 存下 —— 复用它 = AI 记得这个对话的上文
- ⚠️ **引擎建不出来也不报错**（密钥未到位 / 额度 429 / 演示快照模式）：`engineReady: false`，
  改为**首次提问时懒建**。这样引擎抖动不会把「建会话」整个功能拖下水
- 🔴 **`engineSessionId` 绝不出现在任何响应里**，只回一个布尔 `engineReady`（铁律 1）

#### 会话列表

```
GET /api/chat/conversations
```

```json
{ "success": true, "items": [ { "id": "…", "title": "塑料污染治理有哪些主要措施？",

|---|---|
| `messageCount` | 该会话消息条数（一问一答 = 2 条） |

```

#### 删会话

```
DELETE /api/chat/conversations/:id
```

- `{ "success": true }`；**连带删该会话全部消息**（不只靠 schema 的 `onDelete: Cascade`，
  SQLite 的外键级联受 `PRAGMA foreign_keys` 控制，接口层显式先删消息再删会话，两条路都堵死）
- 引擎侧 session 不主动删 —— 它自己会过期
- 会话不存在 → `404 { "success": false, "error": { "code": "CONVERSATION_NOT_FOUND", "message": "…" } }`

#### 带 `conversationId` 提问（接着聊）

`POST /api/ask` 的请求体加**一个可选字段**：

```json
{ "query": "我刚才问了什么？", "conversationId": "7757…" }
```

| 情况 | 行为 |
|---|---|
| **带** `conversationId` | 复用该会话的引擎 session（**不新建** → 上下文连续）；本轮 user 消息开流前落库；流结束后助手全文 + sources 落库；会话 `updatedAt` 置顶 |
| **不带** | 行为与加这个字段之前**完全一致**（一次性问答），**首页旧气泡零改动**、不碰数据库 |
| 会话不存在 | `404 CONVERSATION_NOT_FOUND`（流开始前的普通 JSON，不是 SSE 帧） |
| 建会话时引擎没就绪 | 提问时懒建引擎 session 并回填 |

落库细则（踩过的坑，写下来免得下一个人重踩）：

- **user 消息在开流之前落库**：这样哪怕这次超时/断线/额度耗尽，刷新后也还看得到「我问过什么」，
  而不是自己的输入凭空消失
- **助手回复在 `finally` 里、且必须在 `res.end()` 之前落库**：`res.end()` 一执行本次请求生命周期就结束，
  后面再 `await` 落库会被客户端断开打断，历史里就少这一条
- **只在「有正文且不是错误帧」时写助手消息**：429 / 引擎不可用的错误文案不是回答，
  写进历史会让刷新后的页面出现一条永远答不出来的死气泡
- 落库失败**绝不打断本次问答**（问答是主功能，落库是附加）：全部吞掉，最多 `console.warn` 一行

> ⚠️ **引擎会话的上下文是真的连着的**（2026-10-12 真机实测）：同一 `conversationId` 里
> 先说「我的生日是1995年3月7日，请记住」，再问「我的生日是什么时候？」，
> 引擎答「您的生日是 **1995年3月7日**」。
> ⚠️ 但**模型偶尔会失忆**：同一个会话里问「我刚才问了什么？」，实测两次里一次答得出来、
> 一次答「这是我们当前对话的第一次交流」。这是模型侧的不稳定（不是我们的链路断），
> 演示话术建议避开纯元问题（meta question），换成「上一条里提到的第二点是什么？」这类**指向具体内容**的追问。

### 行为埋点与统计（`POST /api/track` / `GET /api/track/stats`）

实现落在 `backend/src/track/`（**不碰 `docs.ts` / `auth.ts` / `embed.ts` 的既有行为**）。

**上报**：单条、裸数组、`{ "events": [...] }` 三种信封都收；匿名可传（`userId` 缺省即匿名）。

```
POST /api/track
{ "events": [ { "event": "preview", "docId": "k-19", "sessionId": "s-xxx" } ] }
```

| 事件名 | 什么时候报 | 备注 |
|---|---|---|
| `page_view` | 进页面 | PV 口径 |
| `search` | 提交搜索 | 带 `term`，零结果带 `zeroResult: true` |
| `preview` | 打开在线预览 | **服务端已在 preview 接口自动记一条**，前端不必重复报 |
| `download` | 点下载 | **服务端已在 download 接口自动记一条**，前端不必重复报 |
| `ai_ask` | 提问一次 | 带 `noAnswer`（引擎明说没找到答案时为 `true`） |
| `register` | 注册成功 | |
| `feedback_submit` | 提交反馈 | |

- 单次最多 **100 条**；`payload` 序列化后最多 **4000 字符**；不在白名单的事件名一律拒绝
- 逐条校验、**允许部分成功**：`201 { "success":true, "accepted":2, "rejected":[{"index":1,"code":"UNKNOWN_EVENT","message":"……"}] }`
- 信封本身不可用（不是对象/数组、空数组、超 100 条）或**整批全非法** → `400`，body `{ "success":false, "error":{ "code":"VALIDATION_FAILED", "message":"…", "issues":[...] } }`
- 埋点是**旁路**：前端发不出去就吞掉，绝不影响用户操作
- 🔴 **T11：`userId` 统一带上账号**。前端由 `frontend/src/api/track.ts` 的公共出口注入
  （从 `zwp.token` 的 JWT `sub` 取，与 `routes/auth.ts` 签发口径一致），服务端在
  `preview` / `download` / `ai_ask` / `search` 四处 `recordEvent` 里带上 `userIdFromRequest(req)`。
  **未登录一律 null，绝不编造 id**；「游客」这个叫法只在展示层出现（见「使用明细」）。
  ⚠️ T11 之前写入的历史记录 userId **全是 null**，追不回来
- 🔴 **T11：游客权限 `feedback` 关闭时**，未登录请求里的 `feedback_submit` 一律拒收
  （其它事件完全不受影响）：整批都是反馈 → `403 FEEDBACK_CLOSED`；混批 → `201` 且在
  `rejected[]` 里带一条 `{ "code":"FEEDBACK_CLOSED" }`。事件白名单本身没变

**看板**：`GET /api/track/stats`，需请求头 `X-Admin-Token: <ADMIN_STATS_TOKEN>`。

```json
{
  "success": true,
  "generatedAt": "2026-10-07T23:50:00.000Z",
  "totals": { "events": 128, "pv": 42, "uv": 17 },
  "events": { "page_view": 42, "search": 31, "preview": 9, "download": 14, "ai_ask": 26, "register": 3, "feedback_submit": 3 },
  "topSearchTerms": [{ "term": "堆肥", "count": 6 }],
  "zeroResultSearchTerms": [{ "term": "电池", "count": 2 }],
  "topDownloads": [{ "docId": "k-19", "fileName": "2020-生态环境部-…….pdf", "count": 5 }],
  "downloads": { "server": 14, "events": 14 },
  "asks": { "total": 26, "judged": 20, "noAnswer": 3, "unjudged": 6, "noAnswerRate": 0.15 },
  "daily": [{ "date": "2026-10-07", "events": 128, "pv": 42, "download": 14, "ai_ask": 26 }]
}
```

- `uv` = 按 `userId ?? sessionId` 去重的访客数；`noAnswerRate` = `noAnswer / judged`（`judged=0` 给 0，保留 4 位小数）
- `downloads.server` 是**服务端下载接口的权威计数**，`downloads.events` 是前端埋点口径；两者不等说明有绕过前端的直连调用（属正常信息，不是错误）
- 守卫失败：`403 ADMIN_NOT_CONFIGURED`（服务端没配 `ADMIN_STATS_TOKEN`）或 `403 ADMIN_FORBIDDEN`（头不对）——**一律 fail closed，不因为没配就放行**
- 落库位置：`backend/data/track/events.jsonl`（每行一条 JSON，已 gitignore）。数据量级是千行级，无需数据库；将来要换 SQLite 只改 `backend/src/track/store.ts` 一个文件
