## 二、T11-A 游客权限

### 2.1 配置存哪、怎么读写

- 新文件：`backend/data/guest-permissions.json`（与既有 `qa-settings.json` 同风格：小 JSON + 读写工具函数）
- 新接口（`backend/src/routes/admin.ts`，都走 `requireAdmin`）：
  - `GET /api/admin/guest-permissions` —— 返回**开关清单（含默认值+说明）+ 当前值**
  - `PUT /api/admin/guest-permissions` —— 只改传了的项；回读校验后返回

### 2.2 开关清单（**顺序就是这个顺序**，界面照此排）

| # | 键 | 名称 | 建议默认 | 说明（要显示在界面上） |
|---|---|---|---|---|
| 1 | `browse` | 浏览书架与搜索 | **开**（不可关） | 不登录也能看目录，是最低门槛入口；这一项**只读展示、不给开关** |
| 2 | `aiAsk` | AI 问答 | **开** | 产品亮点；关闭后游客提问要提示登录 |
| 2b | `aiAskDailyLimit` | └ 游客每日问答上限 | **5 次** | 配合上一项；`0 = 不限`（🔴 不限会被白刷，耗模型额度） |
| 3 | `preview` | 在线预览 | **开** | 看到内容才有价值 |
| 4 | `share` | 分享 | **开** | 传播要零门槛（纯前端功能） |
| 5 | `feedback` | 意见反馈 | **开** | 有问题就该能说，不必先注册 |
| 6 | `download` | 下载原件 | **关**（要求登录） | 下载是"拿走"，且留痕+引导注册 |

> 「我要投稿」**固定要求登录**，不进这个清单（投稿要能联系到人）。

### 2.3 🔴 后端必须**真拦**（这是本轮的安全核心）

只在界面把按钮藏起来**不算数**——懂行的人直接调接口照样能用。必须在这几处加判断：

| 接口 | 位置 | 拦截逻辑 |
|---|---|---|
| `POST /api/ask` | `backend/src/routes/ask.ts`（现有 `requireLoginForAsk()` 在 81 行、判断在 126 行） | 改成读 `guestPermissions.aiAsk`；关闭 → 401/403 带明确中文原因。**同时**按 `aiAskDailyLimit` 限制**游客**当日提问次数（按「当天 + 游客标识」计数；已登录用户不受限） |
| `GET /api/docs/:id/preview` | `backend/src/routes/docs.ts` | `preview` 关 → 未登录请求 401/403 |
| `GET /api/docs/:id/download` | 同上 | `download` 关 → 未登录请求 401/403 |
| `POST /api/track`（反馈走这里） | `backend/src/routes/track.ts` | `feedback` 关 → **仅拦 `feedback_submit` 事件**，其他事件不受影响 |
| `POST /api/contributions` | `backend/src/routes/contributions.ts` | 不动（本来就要登录） |

- 「未登录」的判定：请求头 **没有** `Authorization: Bearer …`。判定方式与 `contributions.ts` 既有写法保持一致。
- 错误返回用项目既有的错误信封，`message` 要给**人话**（例：`该功能需要登录后使用`），不要甩英文。

### 2.4 前端联动

- 设置页（`frontend/src/views/AdminSettingsView.vue`）新增一块「**游客权限**」：
  - 按上表顺序排列，每项一个开关 + 一句说明；`browse` 显示为**只读**（灰掉或标"始终开放"）
  - 「游客每日问答上限」用数字输入（0 = 不限）
  - 保存后**回读校验**，把哪一项没生效如实显示（与既有智能体设置同一套写法）
- 各功能按配置联动（未登录时）：
  - 关闭 → 按钮**置灰并提示"需登录后使用"**，点击引导去登录页
  - 预览/下载按钮在 `DocDetailView.vue`；分享在 `ShareDialog` 入口；反馈在 `FeedbackDialog` 入口
- 🔴 前端**只是体验**，真正的拦截以第 2.3 节的后端为准。

## 三、T11-B 埋点带上账号

### 3.1 前端（覆盖 page_view / search / ai_ask 等）

- 改 `frontend/src/api/track.ts` 的公共入口（`trackEvent` / `trackBatch`）：
  **统一注入当前登录用户的 id**（登录态见 `frontend/src/api/http.ts` 的 `TOKEN_KEY = 'zwp.token'` 与既有 `useAuth`）。
- 未登录 → `null`（**不要编造 id**）。
- 🔴 **不要改埋点事件名**（白名单是唯一真相），也**不要新增事件类型**。

### 3.2 后端（覆盖 preview / download 这两条服务端埋点）

- `backend/src/routes/docs.ts` 的 `/:id/preview` 与 `/:id/download` 在上报埋点时，从 `Authorization` 头解析当前用户，**把 userId 一并写进事件**；解析不到 → `null`。
- 解析方式与 `contributions.ts` 既有做法一致（Bearer 优先，能复用就复用）。

### 3.3 「游客」这个叫法

- 存储层**不写"游客"这个字符串**，仍然存 `null`；
- **只在展示层**把 `null` 显示成「游客」（T11-C 的表格里）。

## 四、T11-C 数据面板「使用明细」

### 4.1 后端

新接口（`backend/src/routes/admin.ts`，走 `requireAdmin`）：

```
GET /api/admin/usage-detail?date=YYYY-MM-DD     # 省略 date = 今天
```

- 数据源：`backend/data/track/events.jsonl`（逐行 JSON）
- 只统计三类事件：`ai_ask` / `preview` / `download`
- 按 `userId` 分组（`null` → 归到 `guest` 这一组）
- 返回：
```json
{
  "success": true,
  "date": "2026-10-14",
  "rows": [
    { "userId": "abc", "name": "张三", "org": "…", "ai_ask": 3, "preview": 5, "download": 1, "total": 9 },
    { "userId": null,  "name": "游客", "org": "", "ai_ask": 12, "preview": 20, "download": 0, "total": 32 }
  ],
  "totals": { "ai_ask": 15, "preview": 25, "download": 1 }
}
```
- `name` / `org`：用 `userId` 去查本地 SQLite 的 `User` 表补上（**查不到就留空，不要报错**）
- 🔴 文件是**逐日累积**的 JSONL，读的时候按事件里的时间戳筛当天；文件不存在/为空 → 返回空表（**不能 500**）
- 排序：`total` 降序；游客组固定排在最后

### 4.2 前端

- 在 `frontend/src/views/AdminStatsView.vue` **末尾新增**一个区块「使用明细」：
  - 顶部一个日期选择（默认今天）+ 一行合计数字
  - 表格列：**账号**（游客显示为「游客」）/ **AI 问答** / **预览** / **下载** / **合计**
  - 空数据显示"今天还没有使用记录"
- 🔴 **只新增区块**：韶茹写的既有统计逻辑（顶部指标 / 趋势 / 热词 / 热门文件）**一个字节都不许改**。
