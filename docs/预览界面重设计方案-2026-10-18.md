> 日期：2026-10-18 ｜ 出方案人：B 侧（网站前端）｜ 状态：**只出设计，未动一行代码**
> 依据：本地实跑代码与接口（路径与行号都写在各节里），不是凭印象。
> 本方案**不涉及**化学品主题词口径（那条已定，另有信-26 在走）。

## 0. 先说结论与要你拍板的三件事

**结论（一句话）**：把「预览」从**会遮住页面的弹层**改成**页内的一块阅读区**，桌面用「左边列表 + 右边预览」的分栏常驻面板，窄屏塌成全屏抽屉；并且**点资料卡片直接进预览态**，不再先跳详情页。

**我替你补上了原题里两个「待补充」（都是查代码查到的，不是猜）**：

| 原题的空 | 查证结果 |
|---|---|
| 是 `/admin/knowledge` 的预览，还是前台书架的预览？ | **只能是前台**。后台资料管理页 `frontend/src/views/AdminKnowledgeView.vue` 里**根本没有预览功能**（搜 `preview` / `iframe` / `window.open` 零命中）。现在全站有预览的只有三处：资料库列表卡片、资料详情页、详情页「同主题推荐」卡片。 |
| 预览内容是原文、解析结果，还是文件本身？ | **文件本身（PDF 原件）**。前端调 `GET /api/docs/:id/preview` 取回文件流转成 blob URL，塞进 `<iframe>` 给**浏览器自带 PDF 阅读器**渲染（`frontend/src/api/docs.ts:394`）。解析结果只喂知识库做问答，不进预览；`DocDetail.content` 在本地资料模式下是空的，详情页自己也写着「知识库以原件为准，本页不转载正文」。抽样 20/20 份标题都以 `.pdf` 结尾。 |

**要你拍板的三件事**（拍完我就按它排期）：

1. **点卡片是不是不再跳详情页？** 这是全案的开关。是 → 卡片主体点击＝直接开预览；详情信息收进预览面板顶部的「资料详情」入口（`/doc/:id` 路由保留，分享链接照旧能用）。否 → 只把详情页里的预览改成页内展开，别的都不动。
2. **桌面接不接受「左右分栏」？**（列表被挤窄一档，一屏大概 2 列）接受 → 用分栏；不接受 → 退回「页内抽屉/浮层」，列表宽度不变。
3. **超过 20MB 的大文件要不要也能预览？** 库里 16 份（最大 101.2MB）。要支持得动后端（见 §4.4），我列成了待确认项，**没动**。

## 1. 现状对齐

### 1.1 现有预览入口（全部三处）

| 入口 | 文件 | 现在点了会发生什么 |
|---|---|---|
| 列表卡片上的「预览」按钮 | `frontend/src/components/DocCard.vue`（操作行） | 调 `useDocActions().preview()`：先查登录/游客开关 → 超 20MB 直接弹提示不给看 → 取回文件 → **弹出 el-dialog**（`DocPreviewDialog.vue`） |
| 资料详情页「在线预览」 | `frontend/src/views/DocDetailView.vue:290` | 同上，同一个弹窗（`:337`） |
| **卡片主体**（不是按钮） | `frontend/src/components/DocCard.vue` | 跳 `/doc/:id` 详情页 —— **这就是"跳独立页面"的那一跳** |

### 1.2 现状的四个真实摩擦点（都有代码依据）

1. **那一跳有代价**：`router/index.ts` 的 `scrollBehavior` 只处理锚点，其余 `return { top: 0 }`，**没有保存滚动位置**。从列表翻到第 3 页点开一份、再返回，列表回到顶部、还得重新滚 —— 用户感觉「跳页面很烦」的根因在这儿。
2. **弹层是"遮住"而不是"页内"**：`DocPreviewDialog` 是 `el-dialog`（`append-to-body`、`width: min(1080px,94vw)`、`top: 5vh`），底下压着一层遮罩；虽在同一页，观感仍是"来了个独立窗口"。
3. **大文件被直接劝退**：`useDocActions.ts:79` 判断 `doc.size > LARGE_FILE_LIMIT(20MB)` 就只弹一句「文件较大，建议下载后查看」，**不给预览**。
4. **Blob 方案的连带毛病**：文件是整份读进内存再转 blob URL（`api/docs.ts:400`），所以 (a) 才需要 20MB 上限；(b) Chrome 阅读器标题栏只能显示那串 blob UUID（改不了）；(c) 预览状态**不进 URL**，刷新即丢、也没法把"我正在看的这份"发给人。

### 1.3 现状做得对、要保留的

- 取文件的逻辑**只有一份**（`useDocActions.ts`，登录判断/游客开关/大文件限制/中文失败文案都在里面），这是好底子，新方案继续复用它，不新写第二套。
- 游客权限联动、失败时把 blob 里的 JSON 反解成中文（`describeBlobError`）—— 都保留。
- 底部那句格式提示（「对 PDF 效果最好；Word/Excel 空白请下载原件」）—— 保留。

## 2. 路线对比与推荐

| 路线 | 长什么样 | 优点 | 缺点 | 适用 |
|---|---|---|---|---|
| **A. 页内抽屉**（el-drawer，右侧 56vw） | 从右滑出一块面板，列表仍在背后但被遮一半 | 改动小；不像"弹窗" | 遮罩仍在；大屏上左右都浪费；切换下一份要关开 | 只求"别跳页"的最低成本档 |
| **B. 左右分栏常驻面板**（推荐主形态） | ≥1024px：左列表 + 右预览，列表自动收成 2 列 | **列表与预览同屏**，点下一份直接换内容；不丢滚动、不丢筛选；最像"页内" | 要改 `ShelfView` 布局；窄屏必须降级 | 桌面与平板 |
| **C. 弹层增强版**（保留 el-dialog，补 URL 深链/键盘） | 还是弹窗，只是体验补齐 | 改动最小 | "独立窗口"的观感没解决，等于没回答本次问题 | 不推荐，仅作兜底 |
| **D. 独立预览页** `/doc/:id/preview` | 整页阅读器 | 最好读、易分享 | 正是你要去掉的那种"跳页面" | ❌ 不采用 |

**推荐：B + A 组合，加"点卡即预览"**

- **桌面 ≥1024px** → 路线 B（右侧常驻面板，宽 `min(52vw, 760px)`，列表收成 2 列）。
- **窄屏 <1024px** → 路线 A（同一个面板塌缩成右侧全屏抽屉，顶部一个「返回列表」）。
- **两种形态共用一套内部结构**，只是外壳不同（面板 vs 抽屉），避免又出现"两套实现修两遍"（上一轮刚把两套合成一套，不能倒回去）。
- **卡片主体点击 = 打开预览**（不再跳详情页）；完整字段/引用说明仍在 `/doc/:id`，从面板顶部「资料详情」进。
- **理由**：你的原话是「页内显示」或「点开即进入预览态」——分栏同时满足两句话：既在页内，又不用二次跳转；而窄屏用抽屉是因为手机分栏放不下（这一点上一轮已经踩过：手机中段的小面板 PDF 根本读不了）。

## 3. 交互流程

### 3.1 主路径（桌面，分栏）

```
资料库列表 → 点某张卡（任意位置，按钮以外也算）
        ↓（不再路由跳转；列表滚动位置与筛选原样不动）
右侧面板进入「打开中」 → 取回文件 → PDF 铺满
        ↓
面板顶部信息条：文件名 ｜ 类型 · 年份 · 体积 ｜ [下载原件] [复制链接] [资料详情] [×]
底部一行格式提示（沿用现文案）
```

关闭：`×` / `ESC` / 再点同一张卡（toggle）/ 浏览器后退（若用 `pushState` 方案则为后退，见 §4.3）。
关闭后：焦点回到刚才那张卡（键盘用户不丢位置），`?preview` 参数从 URL 移除。

### 3.2 全部分支（这一节是排期要照着做的清单）

| 情形 | 面板表现 | 说明 |
|---|---|---|
| 打开中 | 骨架块 + 「正在打开文件…」转圈 | 沿用现有 spinner 语气；大文件要等 1–2 秒，不能留白 |
| 打开成功 | PDF 铺满；**切换另一份时保留上一份内容直到新的就绪** | 避免每点一次闪一次白 |
| 打开失败 | 图标 + **后端给的中文原因** + [重试] [下载原件] | 原因来自 `describeBlobError`，不要露 `Request failed with status code 404` |
| 未选任何资料（空态） | 居中一行：「从左边选一份资料，这里直接看」 | 分栏模式下才需要；抽屉模式不会有这个态 |
| 超大文件（>20MB，目前 16 份） | 面板内一条说明：「这份 X MB，建议下载后查看」+ 下载按钮 | **改掉现在"弹个提示就结束"的做法**，至少留在面板里 |
| 游客被锁（后台关了预览） | 面板内：「该功能需要登录后使用」+ [登录后预览] | 点按钮走 `/auth?redirect=` 回原页，回来自动重开这一份 |
| 深链接 `/shelf?preview=<id>` | 进页面即打开面板并定位到那份 | 可复制分享、刷新可复现、收藏可用 |
| 深链接指向的 id 不在当前筛选结果里 | 面板照常打开那一份 + 列表上方一行「正在预览的资料不在当前筛选结果中，[清除筛选]」 | 避免"打开了但列表里找不到"的错乱 |
| 键盘 | `ESC` 关闭；`Tab` 焦点进面板；`←/→`（可选）上一份/下一份 | 可选功能，不进 P1 |
| 窄屏（<1024px） | 抽屉全屏，顶部「← 返回列表」 | 就是现在的全屏弹层能读，别退步 |
| 旧链接 `/doc/:id` | 照旧可用（详情页保留） | 不破坏已发出的分享链接 |
| 预览中切换筛选 | 面板保持打开（当前这份仍能看），列表变 | 不做"筛选一变就关掉"的粗暴处理 |

## 4. 工程视角

### 4.1 组件拆分（新增 2 个、改 4 个，改动面可控）

| 动作 | 文件 | 说明 |
|---|---|---|
| 新增 | `frontend/src/components/DocPreviewPanel.vue` | 面板**外壳 + 阅读区**：信息条 / 阅读区 / 底部提示三段的唯一实现；接受 `variant: 'panel' \| 'drawer'`，两种形态只是外框不同 |
| 新增 | `frontend/src/composables/usePreviewPanel.ts` | 预览**状态机**：`closed / opening / ready / error / blocked / too-large`，负责取文件、缓存、`revokeObjectURL`、URL 同步 |
| 改 | `frontend/src/components/DocPreviewDialog.vue` | 现被 3 处引用。**不删**：内部改为薄壳（渲染 `DocPreviewPanel`，`variant='drawer'`），保持对外 props 不变，别的调用方零改动 |
| 改 | `frontend/src/components/DocCard.vue` | 卡片主体点击由 `RouterLink → /doc/:id` 改为 `emit('preview', doc)`；`预览`按钮同一个 emit；**`下载`按钮留在卡片内**（下载不受面板开关影响）。需要给「资料详情」留一个入口（放在卡片的次要位置或面板里） |
| 改 | `frontend/src/views/ShelfView.vue` | 列表区加分栏容器；把 `preview` 状态提升到页面级（不再每张卡各持一份 `useDocActions`）；标题区右侧由筛选区不变 |
| 改 | `frontend/src/views/DocDetailView.vue` | 详情页里的「在线预览」改为**就地展开**（复用 `DocPreviewPanel`，`variant='panel'`，插在正文区上方），不再弹层 |

### 4.2 状态管理

- 预览是**页面级单一状态**（同一时刻只有一份在看），放 `ShelfView` / `DocDetailView` 各一份实例即可，不需要 Pinia。
- 卡片不再各自持有 `previewUrl/previewVisible`（现在 20 张卡 = 20 份 ref），只 `emit`。`downloadingId` 同理可上提（顺带修掉"每张卡各追一份状态"的小隐患）。
- blob 缓存：最近 3 份做 LRU，其余立即 `revokeObjectURL`（现在只在打开新的一份时 revoke 上一份，关闭时不回收 —— 顺手补上）。

### 4.3 路由与 URL 设计

- **用 query，不新增路由**：`/shelf?preview=<docId>`。理由：现有筛选本来就同步在 query 上（`ShelfView.vue:272/277/295`），新增一条 `/shelf/preview/:id` 会让筛选与预览两套 URL 打架。
- ⚠️ **必须做的一件事**：`ShelfView.vue:272` 是 `const query = { ...route.query }` 全量复制，`preview` 会被卷进筛选同步。实现时要把 `preview` **排除在筛选参数之外**（维护一个白名单 `FILTER_KEYS`），否则切筛选会把预览参数写进筛选、或反过来。
- 打开面板用 `router.replace`（不塞历史，避免用户按十几次后退），关闭时 `replace` 去掉参数；**深链接进入**时保留（这样"复制链接"给出去的就是带 `preview` 的地址）。
- 埋点：`router.afterEach` 的 PV 埋点会因为 `replace` 触发吗？—— `afterEach` 在 `replace` 时也会跑，需要给 `preview` 变化加一条"不重复计 PV"的判断（`to.path !== from.path` 时才计数），否则点开预览会多记一次访问。**这条要跟韶茹（`api/track.ts` + 埋点口径）对一下**。

### 4.4 数据来源与需要后端配合的地方（**单独列出，等你确认，我没动**）

| # | 事项 | 为什么要 | 影响面 |
|---|---|---|---|
| B1 | `/api/docs/:id/preview` 支持 **Range / 流式**，并允许「带签名的直链」给 `<iframe>` | 现在整份文件进内存才有 20MB 上限；要支持全部 603 份（含 101.2MB 那份）必须改成流式。iframe 带不了 `Authorization` 头，所以要签名 URL 或 cookie 鉴权 | 后端（韶茹负责的 `backend/src/routes/docs.ts`）+ 契约文档 |
| B2 | 预览 URL 末段带文件名（如 `/api/docs/:id/preview/2026-机构-标题.pdf`） | 现在 Chrome 阅读器标题栏显示的是 blob UUID，用户看不出在看哪份 | 后端小改；不改也不致命（我们自己的信息条已经写了文件名） |
| B3 | 预览失败时返回 JSON 信封而不是流 | 现在已经用 `describeBlobError` 反解兼容了，**可以不改** | — |

> 以上三条**都不做也能上线**（大文件继续走"下载后查看"），要不要做由你定；B1 是唯一会牵动知识库侧（鉴权）的。

### 4.5 性能

- **懒加载**：只有面板打开才发预览请求（现在也是）。点开即预览后，卡片 hover 不预取（避免 20 张卡同时拉文件）。
- **不预取相邻项**（可选 P3）：预测"下一份"要看用户的浏览顺序，收益不确定，先不做。
- 列表侧不用改：603 份走分页 20 条（`PAGE_SIZE = 20`），卡片数量不大，不需要虚拟滚动。
- 面板尺寸变化（分栏 ↔ 抽屉 ↔ 全屏）靠 CSS 与 `el-drawer` 的 `size`，不重取文件。

### 4.6 与全站 Element 风格/空态的一致性

- 用现有组件：`el-drawer`（窄屏）、`el-skeleton`/自定义 spinner（加载）、`el-empty`（空态）、`el-message`（提示），不引新依赖。
- 颜色只用现有 token（`frontend/src/styles/global.css` 里的 `--zw-*`：`--zw-line`、`--zw-mint-2`、`--zw-faint`…），不新造色值。
- **空态文案**：Element 默认英文 `No data`，全站没配中文 locale。建议本次**一并加上全局中文 locale**（一行配置），预览面板与筛选区都会跟着变中文 —— 这件小事你上一条消息里问过，还没拍板，我把它列进 P1 顺手做。

## 5. 视觉与信息层级

### 5.1 桌面分栏

```
┌ 资料库 ────────────────────────────────┬──────────────────────────────┐
│  [全部] [零废弃] [化学品与健康]         │ 文件名（1 行省略）        [×] │  ← 信息条 52px
│  搜索框 · 主题领域 · 知识类型 · 排序    │ 研究实践报告 · 2026 年 · 6.8 MB│
│ ┌────────┐ ┌────────┐                  ├──────────────────────────────┤
│ │ 卡片   │ │ 卡片   │                  │                              │
│ └────────┘ └────────┘                  │        PDF 阅读区            │  ← 铺满，无内边距
│ ┌────────┐ ┌────────┐                  │                              │
│ │ 卡片   │ │ 卡片   │                  │                              │
│ └────────┘ └────────┘                  ├──────────────────────────────┤
│                                        │ ⓘ 在线预览对 PDF 效果最好…    │  ← 底部条 36px
└────────────────────────────────────────┴──────────────────────────────┘
```

- 面板宽 `min(52vw, 760px)`；列表在面板打开时列宽 `minmax(280px, 1fr)`（一屏 2 列）。
- 信息条：文件名 15px/600 `--zw-ink`、单行省略；第二行 12px `--zw-faint`（类型 · 年份 · 体积）；右侧动作**主次分明**：[下载原件] 描边幽灵按钮 → [复制链接] 文字按钮 → [资料详情] 文字按钮 → [×] 图标按钮。
- 分隔：面板左缘 1px `--zw-line`；阅读区背景 `#f6f8f6`（与现弹层一致），PDF 与面板之间不再套第二层框（上一轮刚统一的口径，保持）。
- 面板出现用 180ms 宽度过渡（`prefers-reduced-motion` 下不做动画）。

### 5.2 窄屏抽屉

- 从右侧滑入、占满宽；顶部一行：`← 返回列表` + 文件名（省略）+ `×`；阅读区 `calc(100vh - 150px)`；底部同一句提示。
- 手机上不再出现"面板中段只有 300px 高"的情况（这是当前手机体验差的直接原因）。

### 5.3 详情页就地展开

- 「在线预览」点击后，在按钮下方展开一块同样结构的阅读区（高度 70vh），按钮文案切「收起预览」；不再弹层，也不跳走。
