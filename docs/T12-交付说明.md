### 关键设计决定（两处，都写在代码注释里了）

**① 方向标签的「项」固定、「数字」取实时。**
后端 `buildFacets()` 算某一维时是「排除自己这一维、应用其余维度」，所以 `facets.srcTables`
**会跟着别的筛选一起收窄**。实测（打 4100 的真接口）：

```
[基线] 无筛选                      srcTables = ["零废弃:480","化学品与健康:123"]
[问题] 零废弃 + 类型案例工具        srcTables = ["零废弃:50"]          ← 化学品那条整个消失
[问题] 关键词搜不到任何资料        srcTables = []                    ← 整排标签会消失
```

标签是**导航控件**，不能被筛没了：否则用户选了「案例工具」就再也点不到化学品方向，
只能靠「全部清除」回来 —— 任务单第三节 T12-C 要求的「跨方向自动清类型」也就无从触发。
所以：项 = 挂载时取一次的完整清单（多一次 `GET /api/docs/facets`，无筛选、无新参数）；
数字 = 当前这次 facets，含义是「点这个方向会得到多少份」，当前条件下没命中的方向显示 0，
切过去时 T12-C 清掉失效类型后数字随即变过来（实测 `化学品与健康 0 → 123`）。
这同时也满足了 T12-A.2 的降级要求：数据源没有方向 → 清单空 → 整行不渲染。

**② 方向同步地址栏时，不能让 `applyRouteQuery` 再跑一遍。**
`applyRouteQuery` 的语义是「按地址栏**重新灌一遍**全部筛选」，而关键词、机构、主题、类型
并不都写在 URL 里。所以切方向后 `router.replace` 触发的这次 route 变化必须跳过，
否则用户刚搜完「塑料」点个方向，搜索就被冲掉了。用 `selfPushedPath` 存整条 `fullPath`
来识别（而不是布尔标记：点了已选中的方向时 `replace` 是空操作、路由根本不触发变化，
布尔标记会一直挂着，把下一次真正的导航也吞掉）。已实测：搜「塑料」92 份 → 点零废弃 → 89 份，
关键词 chip 仍在。

## 四、发现但**没有**改的问题（留给主控拍板）

1. **顶部说明句里还留着「方向」二字**：`共收录 603 份资料，可按方向浏览，或按机构、年份、主题、方向组合筛选；…`
   方向已经提到顶部标签上了，这半句里的「方向」现在有点重复。
   **我按任务单「其余不变」的要求只改了前半句**（可按类型切换 → 可按方向浏览），没有自作主张动后半句。
   建议改成「…或按机构、年份、主题、类型组合筛选」，等你一句话我就改。

2. **类型下拉没有跟随方向的「已选项回显」兜底**：`?srcTable=…&type=…` 这种链接，
   若类型在新方向下不存在会被静默清掉（这是任务单要求的静默清理），但地址栏里的 `type=` 不会被改掉，
   刷新一下仍然是「清了的样子」。功能上没问题（每次进来都重新算），只是地址栏与实际筛选状态短暂不一致。

3. **方向标签现在允许多值的老链接仍按「第一个高亮」处理**：`?srcTable=A&srcTable=B`（T8 起参数可重复）
   会同时生效（603 份），但顶部只高亮第一个。多值方向筛选在 UI 上已无入口（改成单选了），
   这类链接基本只可能是历史收藏，按现状留着即可。

4. **数据事实层面（不是前端能改的）**：库里 `各类标准` 两个方向都有（零废弃 23 / 化学品 30），
   `政策法规`（219）只在零废弃、`研究实践报告`(61)/`国内政策法规`(20)/`国际公约`(10)/`科学认知`(2) 只在化学品。
   也就是说「两类资料的类型命名体系本身不完全对齐」—— 若日后想按类型对齐口径，得从数据侧统一，
   本轮**一个字都没改**（红线第 2 条）。
