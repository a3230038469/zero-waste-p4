## 四件事

### 1. 会话存储（乙方案 · 存数据库）

Prisma schema 加两个模型（`backend/prisma/schema.prisma`），`npx prisma db push` 真实落库：

```prisma
model Conversation {
  id               String    @id @default(uuid())
  title            String    @default("新对话")
  engineSessionId  String?   // 引擎侧会话 id，复用它 = AI 记得这个对话的上文
  createdAt        DateTime  @default(now())
  updatedAt        DateTime  @updatedAt
  messages         Message[]
}
model Message {
  id             String      @id @default(uuid())
  conversationId String
  conversation   Conversation @relation(fields: [conversationId], references: [id], onDelete: Cascade)
  role           String      // "user" | "assistant"
  content        String
  sources        String?     // JSON 字符串：T4 来源卡片 [{name,url}]，assistant 才有
  createdAt      DateTime    @default(now())
}
```

新路由 `backend/src/routes/chat.ts`（挂 `/api/chat`，风格对齐现有 routes）：
- `POST /conversations` → 建会话（顺带在引擎建 session，把 `engineSessionId` 存下）
- `GET /conversations` → 列表（按 updatedAt 倒序，带每条的 lastMessage 摘要与条数）
- `GET /conversations/:id/messages` → 该会话全部消息（前端恢复画面）
- `DELETE /conversations/:id` → 删会话（Cascade 删消息；引擎侧 session 不用管，自然过期）
- 这些接口**加不加鉴权**：演示阶段不加用户体系，保持开放，但在注释里写明"交付前若要按用户隔离，在这里挂 userId"
