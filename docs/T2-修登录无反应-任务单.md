# T2 任务单：修「登录成功但像没反应」（云端演示版）

## 病症（已由主控确诊，不是猜测）

1. 云端 `POST /api/auth/login` 返回 200 + 合法 JWT（payload 含 sub、exp=30 天后）
2. 但紧接着 `GET /api/auth/me` 带 `Authorization: Bearer <token>` **10 次全部 401「未登录或登录已过期」**
3. **同一份代码在本机跑完全正常**（本机 register 201 → login 200 → /me 200）
   → 判定：云端环境问题，不是业务代码逻辑错。头部两种可能：①反向代理剥掉了 `Authorization` 头；②多实例密钥不一致。**两种都要能扛住**，所以下面第 1 条用 cookie 兜底。
4. 前端把这个问题变成了「静默失败」：
   - `frontend/src/composables/useAuth.ts` 的 `fetchMe()` catch 后只把 `user` 置 null，**不报错、不清 token**
   - `frontend/src/components/SiteNav.vue` 靠 `user` 判断 → 仍显示「登录 / 注册」
   - 资料详情页的下载/预览按钮也靠 `user` 判断是否已登录 → 一直提示需要登录
   → 用户视角就是「登录完了没反应，什么都点不了」

## 要改什么（4 处，最小改动）

### 1. `backend/src/routes/auth.ts` —— 让凭证有第二条通路 + 可诊断

- `userIdFromRequest(req)`：先读 `Authorization: Bearer <token>`；**读不到就解析 `req.headers.cookie` 里的 `zwp_token`**。
  手动解析 cookie 字符串（按 `; ` 切分、`decodeURIComponent`），**不要新增依赖**。
- `POST /auth/login` 与 `POST /auth/register` 成功时，除了返回 token，**再用 `res.cookie('zwp_token', token, {...})` 落一个 cookie**：
  `{ httpOnly: true, sameSite: 'lax', maxAge: 30*24*3600*1000, path: '/' }`
  （Express 自带 `res.cookie`，不需要 cookie-parser；读的时候我们手动解析。）
- 若文件里已有登出/退出接口，**顺手在该接口里清掉这个 cookie**；没有就**不要新增接口**。
- `/auth/me` 的两种 401 请在响应里区分开（`fail()` 目前只写 message），加一个 `code` 字段便于运维定位：
  - 请求头和 cookie 都没有凭证 → `code: 'AUTH_NO_TOKEN'`
  - 有凭证但 `jwt.verify` 失败 → `code: 'AUTH_BAD_TOKEN'`
  两种的 `message` 保持现有中文不变，**不要把内部细节暴露给用户**。

### 2. `frontend/src/composables/useAuth.ts` —— 别再静默把登录态吞掉

- 导出新增 `isLoggedIn`（`ref` 或 `computed`）：**有 token 就算已登录**，与 `user` 是否取到无关。
- `fetchMe()` 失败时：**保留 token**（现在的行为已经不清，但要显式注释说明），并让 `isLoggedIn` 仍为 true。
- 不要弹全局错误（`silent: true` 保留）。

### 3. `frontend/src/components/SiteNav.vue` —— 导航栏

- 判断改成三级：`user` 有值 → 显示「XX，你好」；否则 `isLoggedIn` 为真 → 显示「**已登录**」；否则才显示「登录 / 注册」链接。

### 4. 下载/预览的登录门槛

- 全仓 grep 一下哪些地方用 `user` 判断“是否已登录才能下载/预览”（重点 `frontend/src/views/DocDetailView.vue`，可能还有 `ShelfView.vue`），**把这些门槛改成 `isLoggedIn`**。
- 只改这一处语义，**不要顺手改别的交互**。
