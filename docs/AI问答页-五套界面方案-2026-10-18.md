## 1. 现状（要摒弃的基准）

`ChatView.vue`（874 行）现在是 **左 264px 会话列表 + 右对话流**：

- 空态：居中大输入框 + 「问一句试试」+ 3 张示例问题卡；
- 对话流：气泡（用户右对齐绿底、AI 左对齐浅绿底、`max-width:86%`），引用是气泡底部横排小 chip；
- 底部：输入条 + 游客限额 + 一行「作答范围；免责声明」；
- 会话列表：标题（首问 20 字截断）、相对时间、条数、末条摘要、删除 ×；
- 窄屏 ≤860px：会话列表变抽屉。

**必须继续承载的功能底线**（设计时一个都不能丢）：新建/切换/删除会话；会话标题与摘要；流式回答 + 等待态；Markdown（含表格）；引用来源（名称 + 机构·年份）→ 跳详情；拒答/无来源/失败三种异常态；游客限额与开关注释；作答范围 + 免责声明；从资料库零结果带 `?q` 预填（不自动发）；手机端可用；自动滚到底、Enter 发送、进页焦点给输入框。

**这次要改的毛病**（五套方案都针对）：① 引用挤在气泡底部，长答案根本看不到；② 气泡两侧留白浪费，一屏只装一问一答；③ 多轮之后找不到"这条引用属于哪一问"；④ 空态除了 3 个示例没有别的抓手。

## 2. 方案一 · 检索台（Search Desk）

**一句话定位**：把问答做成一台"能当场核对的检索台"——答案在中间，出处常驻在右边。

**页面结构与信息架构**（桌面 `grid-template-columns: 208px minmax(0,1fr) 320px; gap:16px`，整屏 `height: calc(100vh - 132px)`）：

```
┌ 侧栏 208 ┬──────── 中列 ────────┬─ 证据栏 320 ─┐
│ 我的对话  │ 提问条（吸顶 56px）   │ 当前回答的   │
│ ·会话…    │ ── 分隔线 ──          │ 引用 1..N    │
│ ───────   │ [问] 问题文本          │ 编号+名称    │
│ 按主题筛   │ 回答正文（15/1.9）     │ 机构·年份    │
│ 塑料/焚烧… │ 引用 3 条 ▾            │ 预览 / 详情  │
└──────────┴──────────────────────┴──────────────┘
```

**关键界面元素与布局**

- 提问条：吸顶、单行、高 56、右侧「发送」按钮；下方一行提示 `Enter 发送 · Shift+Enter 换行`。
- 左栏上半「我的对话」：沿用现在的会话项（标题 / 相对时间 / 条数），选中项左侧 3px 绿条。
- 左栏下半「按主题筛」：取 `facets.tags` 真实词前 8 个（塑料 104 / 垃圾分类 73 / 甲烷 36 / 焚烧 36 …），点击**把词插入输入框**（不自动发），鼠标悬浮提示「插入到提问里」。
- 中列每条问答是一个 `.qa-block`：问题行（`问` 绿色小标签 + 文本 15px/600）+ 答案正文 + 底部一条「引用 3 条 ▾」折叠条（默认收起）。
- 右栏 `.evidence`：**跟随当前聚焦的那条回答**（鼠标移入/点击某条答案即切换），列出该回答的全部引用，每条含序号、名称、机构·年份、体积、「查看详情」按钮；无引用时显示灰字「这一条没有解析到出处」。

**增补（对应体验问题）**

1. **出处常驻右栏** → 答案很长时不用滚到底找引用（现状毛病①）。
2. **聚焦联动** → 多轮对话里"这条引用属于哪一问"一眼可辨（毛病③）。
3. **主题筛词插入** → 不知道能问什么时有个真实抓手（毛病④）。
4. **键盘**：`/` 聚焦输入框、`↑`（输入框为空时）回到上一条问题 → 高频用户少用手。
5. **引用编号与正文上标对应**（1/2/3）→ 用户能说"第 2 条怎么说"。

**视觉主题的应用**：左栏、右栏都是白卡 + 发丝线（与资料库侧栏同语言）；右栏底 `#fbfdfb`，引用条用资料卡的"编号 + 细线"排法，序号 `tabular-nums`；焦点答案左侧 3px `--zw-green`，对应右栏顶部一条同色发丝线，两处颜色呼应。

**与其他方案的差异**：唯一"三栏 + 证据常驻"；信息密度最高、最像工具；手机必须降级（右栏收成底部半屏抽屉，标题「引用 3 条」）。

## 3. 方案二 · 知识卡片流（Card Feed）

**一句话定位**：一问一张"资料卡"，像浏览资料库一样读答案，彻底脱掉聊天气泡。

**页面结构与信息架构**（单列，`max-width:760px`，居中；页面本身滚动）：

```
页头（细）：AI 问答 · 引用可点开原文 ｜ 新建对话
────────────────────────────────
┌ 卡 #3 ────────────────────────┐
│ 问：社区堆肥要注意什么？         │  ← 顶部浅绿条
│ ───────────────────────────  │
│ 回答正文（Markdown）            │
│ ───────────────────────────  │
│ [资料] 堆肥技术指南 机构·2024   │  ← 横排，最多 3 + “+2”
│ 复制答案   追问：关于「甲烷」…   │
└──────────────────────────────┘
```

**关键界面元素与布局**

- 每轮问答 = 一张卡：圆角 14、白底、轻影（**直接复用资料卡的语言**）；卡头左侧 `#3` 轮次编号（`tabular-nums`、12px、faint），右侧时间。
- 用户提问不再右对齐：卡顶一条 `--zw-mint-2` 浅绿条，左侧「问」绿标签 + 15px/600 文本。
- 答案区 15px/1.9，超过 8 行折叠（底部「展开全文 ↓」渐隐遮罩）。
- 卡底两行：① 引用条（横排 chip，最多 3 个 + `+2`，点击跳详情）；② 操作行（`复制答案` / `追问建议`×2）。
- 追问建议由**本条回答的引用主题标签**拼出（例：「关于『甲烷』还有哪些资料？」），点击只填进底部输入框、不自动发送。

**增补（对应体验问题）**

1. **复制答案** → 老师要把结论贴进报告，现在只能手选。
2. **追问建议** → 不知道还能问什么；且只用真实主题词，不虚构业务。
3. **长答案折叠** → 一屏能扫到多轮，不用滚很久。
4. **轮次编号 + 卡时间** → 讨论时能说"第 3 轮那条"。
5. **卡底引用条 + `+N`** → 引用多于 3 条时不撑破卡片。

**视觉主题的应用**：卡片 = `--zw-radius + --zw-shadow-sm + 发丝线`，与 `/shelf` 的卡完全同源；页头用 `.zw-eyebrow`「AI 问答」胶囊；答案里的表格沿用现有 `.md table` 样式（不发丝线以外的重装饰）。

**与其他方案的差异**：唯一"非聊天形态"（没有左右气泡、没有侧栏）；最适合摘录与分享；多会话切换只能靠顶部一个「历史」下拉（比方案一弱）。

## 4. 方案三 · 并排对照（Answer + Evidence）

**一句话定位**：左边答案、右边原文，"它说的"和"原文怎么说的"并排看。

**页面结构与信息架构**（桌面 `grid-template-columns: minmax(0,1fr) 420px`）：

```
┌──────── 对话流 ────────┬──── 原文栏 420 ────┐
│ 问：…（右对齐气泡保留） │ [引用][同主题] tabs │
│ 答：…¹²³ 上标           │ ── 选中引用 ──     │
│ [引用 1] [引用 2]        │ 标题 / 机构 · 年份  │
│                          │ 片段正文（12 行）   │
│                          │ 打开详情 →         │
└─────────────────────────┴────────────────────┘
```

**关键界面元素与布局**

- 左列沿用气泡（用户右对齐、AI 左对齐），但气泡宽度收到 `max-width:72%`，答案里的引用变成**正文上标 ①②③** + 气泡底部三个小 chip。
- 右栏 `position: sticky; top: 84px`，两个 tab：「引用」「同主题资料」。
- 点某个上标或 chip → 右栏就地显示该资料的：类型徽标、标题、机构 · 年份、体积、片段正文（前 ~12 行，超出给渐隐）、「打开详情」按钮。
- 右栏空态一句话：「点回答里的 ①②③，这里显示引用原文」。

**增补（对应体验问题）**

1. **原地读原文** → 现在点引用要跳走，回来丢滚动位置（毛病①的根治版）。
2. **上标 + chip 双通道** → 正文里能定位到"哪句话有出处"。
3. **「同主题资料」tab**（用现成的同主题推荐接口，真实数据）→ 看完一条答案想继续挖。
4. **右栏空态说明** → 第一次进来不会以为右半边坏了。

**视觉主题的应用**：右栏按"纸"来做（`#fff` + 发丝线 + 12px 说明字），不用面板阴影堆叠；上标用 `--zw-green-deep` 12px 上标数字。

**依赖与风险**：片段正文需要接口给（`/api/ask` 的 SSE `references` 里带 `content`，见互通角信-27；**待补充：确认后端是否把片段正文透传到前端**）。手机必须降级：右栏变底部抽屉，点引用上滑半屏。

**与其他方案的差异**：唯一"证据与答案并排、且能读原文"；核对体验最好；但桌面最重、也最像"文献工具"，公众可能觉得复杂。

## 5. 方案四 · 聚焦问答（Focus）

**一句话定位**：首屏只有一个问句，答案出现后输入框沉底——像搜索引擎，不像 App。

**页面结构与信息架构**（单列 `max-width:680px` 居中，两段式布局）：

```
【首屏】           【作答后】
   AI 问答           顶部细条：← 新问题 ｜ 历史 ▾
   一句话说明         ─────────────
 ┌ 大输入框 64 ┐       问：…
 └────────────┘      答：…
 热门主题 chips        ▸ 引用 3 条
 最近问过 · 3 条      ─────────────
                     [吸底输入条 56]
```

**关键界面元素与布局**

- 首屏：`.zw-eyebrow`「AI 问答」+ 一句说明 + 大输入框（高 64、圆角 14、右侧方形「提问」按钮）+ 热门主题 chips（真实 facets 前 6）+ 「最近问过」3 条（取会话列表最近 3 条，点击直接切到该会话）。
- 作答后：顶部细条只留「← 新问题」和「历史 ▾」（历史 = 会话下拉，手机变全屏抽屉）；答案区单列；引用默认折成一行「▸ 引用 3 条」，展开后横排 chip。
- 输入框吸底 56，`position: sticky; bottom: 0`，背板 `rgba(244,248,244,.92)` + `backdrop-filter: blur(6px)`。

**增补（对应体验问题）**

1. **「最近问过」** → 回访者不用重建上下文（现状空态只有 3 个示例）。
2. **引用折叠条** → 省首屏纵向空间，需要时再展开。
3. **滚动过半浮出「回到最新」圆钮** → 长答案里翻上去后回不到底部输入。
4. **加载态骨架 + 等待文案** → 首字之前的空白期有反馈（复用 `useWaitingLines`）。
5. **首屏与作答后是两套密度** → 公众第一次来不会被"对话框"吓到。

**视觉主题的应用**：首屏留白最大化（上 96 / 下 64），背景一层极淡径向绿光（首页 hero 那套语言）；chips 用 `.tag`（`--zw-teal` 字 + `--zw-teal-soft` 底）；发丝线只用在"细条 / 引用条"两处。

**与其他方案的差异**：唯一"两段式布局、单列、无侧栏"；最轻、上手最快、手机最自然；多轮长对话与历史管理最弱。

## 6. 方案五 · 攒料台（Workbench）

**一句话定位**：给做课题的老师用的"攒料台"——边问，边把引用攒成一份清单。

**页面结构与信息架构**（`grid-template-columns: 240px minmax(0,1fr) 300px`）：

```
┌ 会话 240 ┬────── 对话 ──────┬── 我的清单 300 ──┐
│ 新建      │ 气泡流（沿用）    │ 1 塑料回收指南    │
│ 会话…     │ 每条答案右上 ⋯    │   机构 · 2024  ✕  │
│           │                  │ 2 …              │
│           │                  │ [复制为引用列表]  │
└───────────┴──────────────────┴──────────────────┘
```

**关键界面元素与布局**

- 左：会话列表（同现状）。
- 中：气泡流（沿用现状），答案气泡右上角一个 `＋ 收进清单` 小按钮；每条引用 chip 右侧也有一个 `＋`。
- 右：`.clipboard` 清单——序号 + 标题 + 机构·年份 + 移除 ✕；底部「复制为引用列表」生成多行文本：
  `1. XXX 指南（安徽省…基金会，2024）`。
- 空态：「在回答的引用上点 ＋，攒成一份可复制的清单」。
- **数据边界（必须在 UI 上写明）**：清单只存在本机浏览器（`localStorage`，键 `zwp.clipDocs`），换设备/清缓存会丢；不涉及后端与账号。

**增补（对应体验问题）**

1. **引用一键收进清单** → 问到好东西但记不住是哪份资料（真实痛点，老师要做资料汇总）。
2. **清单可复制为规范引用文本** → 直接贴进报告/邮件，省手工整理。
3. **清单条目可点开详情** → 回到原件核对。
4. **"关键结论"钉住**（本页顶部一条 1 行摘要，点开回到那条答案）→ 长对话回溯。

**视觉主题的应用**：清单条 = 资料卡的"编号 + 发丝线"；`＋` 变 `✓` 用 `--zw-green`；底部按钮用 `el-button plain`（次操作不抢主操作）。

**与其他方案的差异**：唯一带"跨问答资产"的结构；最贴公益机构的真实用法（做汇总）；但功能最多、实现成本最高，且清单是本地数据（要说清）。

## 7. 横向对比与推荐

| 维度 | 一 检索台 | 二 知识卡 | 三 并排对照 | 四 聚焦问答 | 五 攒料台 |
|---|---|---|---|---|---|
| 信息密度 | 高 | 中 | 高 | 低 | 高 |
| 出处可见性 | ★★★（常驻） | ★★（卡底） | ★★★（可读原文） | ★（折叠） | ★★（可收清单） |
| 上手门槛 | 中（三栏） | 低 | 高 | **最低** | 中 |
| 多轮/历史管理 | ★★★ | ★ | ★★ | ★ | ★★★ |
| 手机适配 | 差（要降级） | 好 | 差（要降级） | **最好** | 中 |
| 实现成本（估） | 3–4 天 | 2–3 天 | 4–5 天（含片段接口） | **1.5–2 天** | 3–4 天 |
| 适合谁 | 研究者核对 | 公众浏览/摘录 | 需要引原文的评审 | 第一次来的公众 | 做汇总的老师 |

**推荐**：**以方案四为骨架、方案二为"答案长什么样"**——首屏单列聚焦（公众第一眼不吓人、手机零改造），多轮之后的每条答案按方案二做成"卡片"（顶部浅绿问题条 + 卡底引用条 + 复制/追问建议）。两套的组合正好补上彼此的短板：四的答案是普通气泡，二的答案是好读的卡。

理由三条：① 站点气质是"留白 + 纸面"，三栏密度与它相冲；② 主人前面已经明确否掉过卡片详情页的左右分栏，三栏方案（一/三/五）大概率同样被否；③ 成本最低，且增补项全是前端能落地的（热门主题、最近问过、复制、追问建议都由现有接口拼出）。

如果更看重"核对"，就把方案三的右栏原文**只放进详情页**（点引用进详情、在详情页右侧显示原文），问答页保持单列——这是把三的强项搬进四的最省力做法。
