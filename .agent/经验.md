## E1 跟人对接的任务，一律"任务单 + 交付说明"两份
- **场景**：主控派活给队友 / 执行方，或验收别人交来的东西。
- **无效尝试**：只在聊天里口头交代 → 事后对不上"当初到底要什么"，双方各说各话。
- **最终打法**：派活时写 `docs/T<n>-<名字>-任务单.md`（做什么、边界、验收标准、落盘路径）；干活方交 `docs/T<n>-交付说明.md`（实际改了什么/怎么验的/还剩什么要拍板）。**交付说明只写"实际改了什么"**，所有结论性描述都要对应仓库里的代码或一次真实运行。
- **怎么验证**：对照任务单逐条打勾；缺"交付说明"的批次不验收。
- **下次用在哪**：任何多人/多 AI 协作的项目。

## E2 结论必须带"实测回显"，"我做完了"不算数
- **场景**：验收队友或 AI 的交付。
- **无效尝试**：信汇报 → 本项目**铁律是"不互信汇报、各自实测对账"**，别人的汇报不能信。
- **最终打法**：要求回报里贴**文件路径 + 实测命令回显**；主控**亲跑一遍**关键命令（`/health`、`/api/docs?limit=1` 应 603、`docker ps` 应 5 容器）。
- **怎么验证**：命令回显与声称一致。
- **下次用在哪**：所有验收场景。

## E3 github.com 被墙时的推送办法
- **场景**：国内网络下 `git push/fetch` 时通时不通。
- **无效尝试**：反复重试 `git push`（撞运气，浪费十几分钟）。
- **最终打法**：`github.com` 会断，**`api.github.com` 一直是通的** → 走 **Git Data API**：blob → tree → commit → `PATCH ref`。⚠️ 坑：`base_tree` **必须从 commit 对象的 `.tree.sha` 取**，不能用 trees 端点的回显。查远程状态一律用 `gh api`（不依赖 git 通道）。
- **怎么验证**：`gh api` 查到的 ref 与你本地 HEAD 一致。
- **下次用在哪**：本仓库所有推送；任何国内推 GitHub 的项目。

## E4 验证本机服务必须加 `--noproxy '*'`
- **场景**：`curl http://127.0.0.1:4000/health` 明明服务在跑却取不到。
- **无效尝试**：以为服务挂了、重启后端（白折腾）。
- **最终打法**：本机系统/沙箱代理会把 `127.0.0.1` 的请求转走 → `curl` 一律带 `--noproxy '*'`。
- **怎么验证**：加上后立刻返回 `{"ok":true}`。
- **下次用在哪**：任何本机端口自检。

## E5 AI 起的常驻进程活不过一次工具调用
- **场景**：想让 AI 把本地网站"一直开着"。
- **无效尝试**：后台起守护进程、关沙箱——**都一样**，工具调用一结束进程就被回收。
- **最终打法**：接受这个限制——**本地站只能由人双击 `打开零废弃知识库.cmd` 启动**；AI 只负责"验证它能起来"并把结果报出来。
- **怎么验证**：起完立刻 `curl --noproxy '*' /health` 能通，但下一次调用就没了。
- **下次用在哪**：所有"需要常驻本机服务"的活——**别承诺"我帮你一直开着"**。

## E6 追加式日志绝对不许"重写最后一段"
- **场景**：多 AI 共写同一份改动日志。
- **无效尝试**：为"顺便优化格式"替换/重写既有段落 → **覆盖过别人的记录**（已发生过一次）。
- **最终打法**：追加式文档**只允许在末尾追加**；要改历史只能新增一条"更正"。
- **怎么验证**：`git diff` 里不出现被删的旧行。
- **下次用在哪**：任何"日志 / 台账 / 迭代记录"类文件。

## E7 「官方说不能做」先抠原文措辞：不建议 ≠ 禁止（原库内 `.agent\经验.md` E1，2026-10-18 并入）
- **场景**：判断某技术路线是否撞红线（RAG / 官方指引）。
- **无效尝试**：按"官方不建议"直接判为禁止，把它列成阻塞项（当时差点因此换方案）。
- **最终打法**：回原文抠措辞——"不建议"是倾向、不是禁令；分清之后再定路线。
- **怎么验证**：小志 2026-09-29 13:31 澄清；随后确定走 WeKnora（见 `决策.md` 2026-10-13）。
- **下次用在哪**：任何"官方文档说不行"的判断，先分清楚是**禁止**还是**不推荐**。

## E8 一个项目只能有一个实体，否则定位必然分叉（2026-10-18）
- **场景**：同一个项目的文档分散在两处——库内 `1-项目\AI向善实战营`（课程/团队）与本仓库（代码/交付）。
- **无效尝试**：两边各留一套文档 + 各留一套 `.agent\`，靠"指针互相指"维持一致。
- **最终打法**：**实体只留一处**（本项目 = 本仓库），库内只保留"主控记录"（一行索引 + 记忆分区）；两套 `.agent\` 合成一份，条目按日期追加。
- **怎么验证**：全库 grep `1-项目\AI向善实战营` 与 `E:\obsidian\大学生\1-项目`，确认只剩"已并入"的说明性引用；两侧 `git log` 留有合并前快照，可整包回退。
- **下次用在哪**：任何"库里记一份、盘上放一份"的长期项目——**开工时就定死实体位置**，别等两边都长起来再合。
