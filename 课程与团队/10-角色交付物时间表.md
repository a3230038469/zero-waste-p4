## 二、按角色看（每个位置要产出什么）

| 角色 | 要交的东西 | 关键时间点 |
|---|---|---|
| **组长** | 团队说明书（统稿）、每周进度同步、DEMO day 演示、成果汇报材料 | 9.22 / 全程每周 / 10.10 / 10.19-21 |
| **调研负责人** | 机构访谈记录、需求清单、需求文档（与产品一起） | **访谈后立刻** / 9.26 |
| **产品负责人** | 功能清单、"做什么不做什么"的边界、页面结构 | 9.26 / 10.8 前 |
| **技术负责人（＋助手）** | 能跑的原型 → Demo MVP → 迭代版 → 终版链接 | 10.8 / 10.10 / 10.15 / **10.22** |
| **设计负责人** | 页面视觉、宣传文案、汇报物料 | 10.8 前 / 10.19 汇报前 |

> **三种节奏不一样，选之前先想清楚**：
> - **天天有活**：技术、调研
> - **阶段性出东西**：产品、设计
> - **全程收口**：组长
> 按"我这一个月每周能拿出多少时间"来选，比按"我对哪个词感兴趣"选靠谱。

## 三、今天只需要定一个岗：调研负责人

**为什么是他先定**：机构老师还没进群，需求一天不清楚，后面全是空转。调研负责人是**唯一一个"现在不动就拖全组"的位置**——因为他的产出（需求）是 ② 产品需求文档 的输入，而 ②又是 ③ Demo MVP 的输入。

**他具体干什么**：
1. 对接机构老师（进群后第一时间约上沟通）
2. 挖真实需求（分清"他们说的"和"他们真正缺的"）
3. 写访谈记录 + 需求清单
4. 和产品负责人一起出产品需求文档

**对他的要求**：能问、敢追问、愿意整理文字、**时间相对稳定**。
