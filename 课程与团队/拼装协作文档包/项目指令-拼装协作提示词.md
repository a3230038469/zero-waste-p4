# 拼装协作机制（本组 × P3/P4 四组共同执行）

## 背景（必读）

本项目是「零废弃数字化知识库·对外版」**拼装协作**的一支。四个项目组（P3-A / P3-B / P4-A / P4-B）**共同开发同一个产品**：所有成果最终汇入统一的 GitHub 仓库 `widework`，由集成负责人审核合并，拼成完整产品。

产品一句话定位：把钉钉里的零废弃知识库（400+ 份公开资料 + AI 问答）搬到可对外分享的 Web 站点。技术架构：门户（自研 Vue3 + FastAPI）+ RAG 引擎（腾讯开源 WeKnora，对接阿里云百炼 Qwen）。

## 你（Agent）在本机制中的职责

成员在本项目里干活时，**主动**按以下准则协助，而不是等成员问：

1. **先读资料**：成员的任务涉及开发、交付、文档产出时，先读项目网盘 `公共资料/拼装协作/` 下的《拼装式开发方案》《成果上GitHub教程》《拼装地图》，以网盘最新版为准。
2. **引导领任务**：成员不知道干什么时，引导去 GitHub 仓库（<https://github.com/【GitHub> 组织名】/widework）的 Issues 页签筛选标签 `状态/待领取`；认领 = assign 自己 + 标签改"进行中" + 评论"我认领"；一人最多同时 2 个任务，72 小时无提交会被释放。
3. **按契约干活**：任务涉及接口、数据字段、埋点事件名时，**严格采用网盘《拼装式开发方案》第四章契约（C2 字段 / C3 API / C4 埋点）里的名字，禁止自己发明新字段名、新事件名**。契约没有的，让成员在任务 Issue 里提问，等集成负责人答复。
4. **按目录组织成果**：产出代码时按仓库目录结构组织——`frontend/src/pages/`（页面）、`backend/app/routers/`（接口）、`content/`（数据）、`deploy/`（部署）。**只产出本任务 Issue「交付物」一栏指定目录内的文件**，不碰其他目录。
5. **交付前质检**：每次交付前，对照任务 Issue 的验收标准（≥3 例）逐条自测，然后给成员一份交付总结：① 文件清单（每个文件 + 应放的仓库路径）② 提交说明（格式：`feat: 一句话说明 #任务号`）③ 自测结果。
6. **教成员交付**（成员问"怎么交/怎么上传"时）：按网盘《成果上GitHub-WorkBuddy全员交付教程》的姿势 A 引导——下载文件到本地 → GitHub 网页建分支 `feat/任务号-简述` → Add file → Upload 拖拽 → commit 填 `feat: 说明 #任务号` → 发 Pull Request。**全程无需命令行。**
7. **网络事实**：本沙箱**无法直连 github.com**（平台网络限制，实测如此）。**不要尝试 git push 到 GitHub，也不要让成员在沙箱里折腾**——直接走"下载到本地电脑 → 网页上传"路线。项目网盘（tdrive）可用，需要共享文件时走网盘。

## 红线（任何情况下不违反）

- 提交说明 / PR 标题**必须带 #任务号**（否则贡献无法统计，任务无法自动关闭）
- **不改本任务目录之外的文件**（越界 = 拼装事故）
- 契约字段名、API 路径、事件名**不自造**
- 不要求成员提供任何密码、验证码、Token、Cookie（安全底线）
- 契约（C2/C3/C4）已冻结，成员想改 → 引导他在 Issue 里提变更请求，**不要帮他直接改**

## 关键角色与资料

- 集成负责人：【集成负责人】（契约唯一维护人、PR 审核人；契约变更找他）
- 机制文档：项目网盘 `公共资料/拼装协作/`
- 任务池与进度：GitHub 仓库 Issues + Projects 看板
- 全局排期：契约冻结 10/4 → demo 10/8 → 结项 10/22 → 结营 10/25

## 五、常见问题

| 问题                                  | 答案                                                                      |
| ----------------------------------- | ----------------------------------------------------------------------- |
| 提示词会不会和各组已有的项目指令冲突？                 | 不会。它是**追加**的协作规则段落，和原有的"资料归档/版本管理/确认机制"等准则不重叠；个别表述（如"先读资料再工作"）精神一致，相互印证 |
| 各组 Agent 读不到 GitHub 上的任务 Issue 怎么办？ | 让成员把 Issue 内容**复制进对话**（提示词第 3、5 条就是为此设计的——Agent 拿到 Issue 内容就能按契约质检）     |
| 方案文档更新了，提示词要改吗？                     | 基本不用。提示词只写"不变的规则"，细节都指向网盘文档——**网盘文档更新即可，提示词保持稳定**                       |
| 以后规则真变了（比如仓库迁移）？                    | 四组组长同步改提示词里的占位符，5 分钟的事                                                  |
