# 实验报告 · WeKnora 能否承载钉钉表格那五列（阶段零 V1 扩展）

## 实验问题

钉钉多维表格的列（知识名/发布机构/发布年份/类型/领域多标签）能否在 WeKnora 原生承载？书架页的筛选排序怎么做？

## 实测结果

| # | 实验 | 结果 | 证据 |
|---|---|---|---|
| 1 | 写自定义元数据（年份2026/类型/领域/机构 四字段）到已有文件 | ✅ HTTP 200，读回完全一致 | `PUT /knowledge/:id` + `GET` 读回 |
| 2 | 列表接口是否带出自定义元数据 | ✅ 原样带出 | 列表 JSON 含完整 `custom_metadata` |
| 3 | keyword 搜索能否命中元数据值 | ❌ **不命中**（搜"测试机构"0 命中；搜文件名"成图"1 命中） | list?keyword= |
| 4 | 列表 API 有无按元数据筛选/排序参数 | ❌ 无（只有 tag_ids/keyword/file_type/folder/sort_by=updated_at\|created_at\|file_name） | 官方文档 + 实测 |
| 5 | API 给已有文件挂标签 | ⚠️ **未生效**：`PUT tags:[tag_id]` 与 `tag_ids` 两种键名都返回 200 但 `knowledge_count` 仍为 0、过滤无效 | POST /tags 建标签成功；挂载两次均无效 |
| 6 | AI 自动摘要/主题/文档类型 | ✅ 上传后自动生成（profile 含 gist/topics/doc_type） | 文件详情 |

## 设计结论（回答"表格效果怎么做"）

1. **五列全部进 WeKnora**：知识名=文件名、PDF=文件本体、四列业务字段=custom_metadata（最多 20 项，够用）、领域标签=tags（UI 挂或自动打标）+ custom_metadata 里同时保留一份"知识领域"文本字段做兜底。
2. **书架页的筛选/排序在自建后端做**：WeKnora 列表不支持按元数据筛排 → 自建后端把 WeKnora 的知识列表（含 custom_metadata）定时同步进 SQLite 做索引，书架筛选（机构/年份/类型/领域）查自己的索引，文件本体与问答仍单源走 WeKnora。**这正是规划里 SQLite 的定位，不违背"文件只存一份"**。
3. **检索三通道分工**：文件名搜索走自建索引（含清洗分词）；全文语义问答走 WeKnora knowledge-chat；元数据筛选走自建索引。互不冲突。
4. **标签挂载走 UI 或自动打标**，API 挂标签这条路 v0.8.2 存疑——不阻塞（领域信息已在 custom_metadata 兜底），留一条开放问题。
