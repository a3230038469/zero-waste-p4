# 需求报告模板 + 给机构的确认清单

## 一、需求报告（存为 05-需求报告.md）

```markdown
# <机构名> · 需求报告
> 版本：v1　｜　日期：YYYY-MM-DD　｜　撰写：<团队>　｜　基于：<访谈轮次 + 材料来源>

## 一、背景
<机构在做什么、我们怎么认识的、这份报告基于哪些材料>

## 二、问题定义
> <谁> 在 <什么场景> 下，因为 <根因>，导致 <损失>。
<一句话讲清，不加修饰>

## 三、证据
| # | 原话/数据 | 来源 | 时间 |
|---|---|---|---|

## 四、目标用户与使用场景
| 用户 | 什么场景下用 | 想达成什么 |
|---|---|---|

## 五、这一阶段做什么
| # | 功能 | 解决哪条痛点 | 最小可接受标准 |
|---|---|---|---|
| 1 | | P1 | |

## 六、不做什么（本阶段）
| # | 不做的事 | 为什么不做 | 什么时候再考虑 |
|---|---|---|---|
| 1 | | | |

## 七、怎么算做成了
| 指标 | 现在 | 目标 | 怎么量 |
|---|---|---|---|

## 八、还需要机构确认的事
| # | 要确认什么 | 期望回复 |
|---|---|---|

## 九、开放问题与风险
- <还没搞清、可能影响方案的事>
```

**报告纪律**：第五节每条功能必须能追到第四节的用户场景和第三节的证据；追不到的删掉。第六节不许为空。

## 二、给机构的确认清单（一页，单独发给机构）

```markdown
# <机构名> · 请确认这几件事
> 不用写长回复，逐条打勾或回一句就行。

1. 我们理解的问题是这样：<一句话问题定义>。　　　☐ 对　☐ 不对（请指出）
2. 我们打算先做：<功能 1>、<功能 2>。　　　　　　☐ 可以　☐ 需要调整
3. 这一阶段我们不做：<不做什么清单摘要>。　　　　☐ 同意　☐ 有意见
4. 我们最想达到的效果是：<指标>。　　　　　　　　☐ 认可　☐ 请换一个
5. 下一步想再约 <时长> 分钟，时间建议：<选项>。　☐ 可以　☐ 换个时间

还有一句想说的：
```

**使用要求**：这份清单必须在需求报告之后发，不要提前发；机构每一条都回复后，才算本轮需求确认完成。

## 三、报告写完后自查

- [ ] 问题定义是一句话，且指向能动手的根因
- [ ] 第五节每条功能都能追到痛点清单的条目编号
- [ ] 第六节"不做什么"非空，且写了"什么时候再考虑"
- [ ] 第七条指标现在值和目标值都能写出来
- [ ] 第八条只列真正需要机构拍板的事，不超过 5 条
- [ ] 全文没有把推断写成事实
