# 痛点分析清单模板

```markdown
# <机构名> · 痛点分析
> 分析日期：YYYY-MM-DD　｜　材料来源：<谁、什么时候、什么场合>　｜　材料未覆盖：<哪些环节没聊到>

## 一句话问题定义
> <谁> 在 <什么场景> 下，因为 <根因>，导致 <损失>。

## 痛点明细

### P1 · <标题>
| 项 | 内容 |
|---|---|
| 表层现象 | "<对方原话>" |
| 追问链条 | 见下 |
| 根因 | <能动手改的那一层> |
| 所在环节 | <七条链路之一> |
| 原话证据 | "<原话>" —— <谁>，<时间点> |
| 频次 | 每天 / 每周 / 每月 / 只出现过一次 |
| 影响 | 1 / 2 / 3 |
| 可验证 | 1 / 2 / 3 |
| 得分 | 频次 × 影响 × 可验证 = <分数> |
| 来源标记 | 【他们说】/【我们推，待确认】 |

**追问链条**
```text
表层：<原话>
└─ 为什么？ → <回答>
   └─ 为什么？ → <回答>
      └─ 为什么？ → <回答>
         └─ 为什么？ → <回答>
            └─ 为什么？ → <回答>  ← 根因
```

### P2 · <标题>
（同上结构）

## 条件依赖的条目

| 条目 | 前提 A 下的回答 | 前提 B 下的回答 | 是否硬需求 |
|---|---|---|---|
| | | | 是 / 否 |

## 排序总表

| 排序 | 痛点 | 得分 | 证据强度 | 谁说的 |
|---|---|---|---|---|
| 1 | | | 有原话 / 仅推断 | |

## 被排除 / 降级的条目

| 条目 | 原因 |
|---|---|
| | 频次太低 / 只有一个人提 / 无法验证 / 是方案不是需求 |

## 需补问的事实

| # | 要问什么 | 问谁 | 为什么现在判断不了 |
|---|---|---|---|
| 1 | | | 材料里只有评价，没有事实 |

## 材料内部的矛盾

| 说法 A | 出处 | 说法 B | 出处 | 处理 |
|---|---|---|---|---|
| | | | | 并列待确认 |
```

## 填写示例（片段）

```
### P1 · 内容发布通道被卡住
| 项 | 内容 |
|---|---|
| 表层现象 | "知识库的前端页面和操作路径待优化" |
| 根因 | 内容与问答被绑在需要登录的平台内，外部访客拿不到 —— 卡在发布通道，不是内容质量 |
| 所在环节 | 受益人连接 |
| 原话证据 | "因平台限制，下载功能与 AI 助理功能需在特定平台内使用，暂无法对外" —— 机构方，<时间点> |
| 频次 | 每天 |
| 影响 | 2 |
| 可验证 | 3 |
| 得分 | 3 × 2 × 3 = 18 |
| 来源标记 | 【他们说】 |
```

**填写要求**：示例仅示范结构。每条的得分依据要能被别人复核；同一批材料必须用同一套口径打分。
