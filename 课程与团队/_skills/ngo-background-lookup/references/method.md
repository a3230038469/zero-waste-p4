# 检索与判断细则

## 检索顺序与优先级

| 顺序 | 找什么 | 为什么排这个位置 |
|---|---|---|
| 1 | 官网"关于我们""年度报告""信息公开"栏目 | 机构自述，口径最准 |
| 2 | 公开披露平台的年报与财务信息 | 有统计口径，可交叉验证 |
| 3 | 官方公众号近一年推文 | 能看出实际在跑什么项目 |
| 4 | 媒体报道、行业奖项、资助方公告 | 佐证影响力与资源结构 |
| 5 | 合作方、联合发起方名单 | 判断它在哪张网络里 |

**来源分级**：机构自述 > 公开披露 > 权威媒体 > 行业转载 > 无法判断来源的内容。低级别来源只能用来"找线索"，不能当结论。

## 四要素体检的判读要点

| 要素 | 看得出什么 | 常见盲区 |
|---|---|---|
| 身份与合规 | 规模、年限、业务范围、透明程度 | 只看到"有官网"就以为规范 |
| 资源获取 | 钱的结构决定它的优先级 | 把某一年的大额捐赠当成常态 |
| 服务转化 | 它到底有没有在交付具体服务 | 把"计划做"当成"正在做" |
| 影响力反馈 | 它靠什么证明自己有效 | 只看它自己说的成果 |

**一条经验**：资金结构决定核心业务。主要靠公众月捐的，传播和透明度是生命线；主要靠政府购买服务的，项目书与合规是生命线。判断它卡在哪，先看钱从哪来。

## 业务引擎定位表

| 引擎 | 卡住时的典型表现 |
|---|---|
| 筹款 | 收入结构单一，靠一两个大额来源 |
| 立项书撰写 | 频繁投标、中标率低、没有筛选标准 |
| 志愿者招募与管理 | 招募靠人情、流失快、没有留存机制 |
| 活动运营 | 活动依赖个别骨干，复制不了 |
| 受益人连接 | 内容和能力都有了，触达不到需要的人 |
| 多方协作 | 资源在手里但协调不动 |
| 内部合规 | 披露、审计、留痕靠临时补 |

**判断纪律**：写"可能卡在 X"，必须同时写出至少一条公开证据（或明确写"暂无公开证据，属推断"）。

## 信息冲突与缺口处理

- **冲突**：两个来源说法不一致 → 两说并列，标明来源和日期，标 `【信息冲突，待确认】`，不自行取舍。
- **缺口**：查不到就写"未找到"，并转成一条"待向机构核实的问题"。
- **过期**：优先用最近 12 个月内的信息；引用多年前的数据要注明年份。

## 待核实问题的写法

好问题长得像这样：

- "你们的资金里，月捐、政府购买服务、企业捐赠大概各占多少？"
- "去年到今年，这个项目一共服务了多少人？大概怎么统计的？"
- "现在谁在负责这块？一个人还是几个人？大概占多少精力？"

差的问题：问"你们的痛点是什么"（太大，对方答不了）、问"是不是缺一个系统"（替对方想方案）。
