# 总体指挥板（P3 + P4 联合）

> 这份东西只解决一个问题：**12 个人同时做一个网站，怎么才能不打架、还能拼在一起。**
> 定完就锁死，之后所有人照着它干，不再开"分工讨论会"。

---

## 一、先说清楚：为什么不能"直接分活了"

12 个人一起做，**最怕的不是活多，是四种情况**：

| 情况 | 后果 |
|---|---|
| 两个人改同一个文件 | 互相覆盖，改到第三轮谁都说不清哪版是对的 |
| 一个人做的页面，用的字段名跟另一个人不一样 | 拼装时对不上，全部返工 |
| 有人做完自己的，发现"要等别人先出东西" | 空转，进度被最慢的人卡住 |
| 各写各的技术方案 | 12 个物种，最后拼不起来 |

**这四种都不是"态度问题"，是"没立规矩"。** 下面三节就是规矩。

## 三、网站全貌（先把"要做哪些页面"摆出来）

网站结构**控制在 4 层以内**（官方建议 ≤5 层）。

```
第 1 层  首页 / 书架页  ← 进来就看到全部资料，按类型/主题/年份浏览
第 2 层  ├ 检索结果页      ← 搜文件名 + 筛选 + 排序
         ├ 分类浏览页      ← 按类型 / 主题 / 年份进
         ├ AI 问答页        ← 提问、看回答、看来源
         ├ 上传提交页      ← 用户提交资料
         └ 反馈页
第 3 层  ├ 文件详情页      ← 预览 PDF + 下载
第 4 层  └ 管理后台（需登录）
             ├ 文件管理（增 / 改 / 删）
             ├ 审核队列
             └ 使用统计
登录 / 注册页（独立，进站先过）
```

**一共 12 个页面/功能块** —— 和 12 个人正好对上。

## 四、⭐ 数据契约（这一份是全项目唯一的真相）

**为什么它最要紧**：所有人都不用等别人，就是因为"字段"先定死了。

| 字段名（英文，前后端统一用） | 类型 | 取值 / 说明 | 谁填 |
|---|---|---|---|
| `file_id` | 文本 | 系统生成唯一编号 | 系统 |
| `title` | 文本 | **文件名（去扩展名）** ← 检索只搜这个字段 | 导入 |
| `publisher` | 文本 | 发布机构 | 黄正的 Excel |
| `year` | 数字 | 4 位年份 | 黄正的 Excel |
| `type` | 单选 | 研究报告 / 政策法规 / 案例工具 / 各类标准 | 黄正的 Excel |
| `topics` | **多选** | 自定义主题标签（一条资料可有多个） | 黄正人工打标 |
| `file_url` | 文本 | PDF / Word 文件地址 | 导入 |
| `file_format` | 单选 | PDF / Word | 导入 |
| `status` | 单选 | 待审核 / 已入库 / 已拒绝 | 系统 |
| `source` | 单选 | 官方导入 / 用户上传 | 系统 |
| `uploader` | 文本 | 提交人（用户上传时才填） | 用户 |
| `created_at` | 日期 | 入库时间 | 系统 |
| `download_count` | 数字 | 下载次数（统计用） | 系统累加 |
| `view_count` | 数字 | 浏览量（统计用） | 系统累加 |

**三条使用规矩**（违反就是给全组埋雷）：

1. **检索只搜 `title`** —— 黄正明确说"只搜文件名，不做全文检索"。
2. **筛选用 `type` / `topics` / `year`，排序用 `year`** —— 就这三个，别自己加。
3. **任何人都不能私自加字段**。确实需要 → 提给 M1（数据负责人）→ 由他改契约并通知全员。**私自加字段 = 别人做的页面直接崩。**

## 六、三条拼装规矩（这是"互不影响还能打通"的全部秘密）

### 规矩 1：文件所有权 —— 一个文件只能一个人改

**做一张「文件归属表」**（下面这个格式），写明"谁碰哪几个文件"。**其他人一律不改。**

| 模块 | 归属人 | 只允许改这些文件/目录 |
|---|---|---|
| M2 骨架 | 徐韶茹 | `src/app/layout.*`、`src/app/page.*`、`src/components/` |
| M3 检索 | （待定） | `src/app/search/**` |
| M4 详情 | （待定） | `src/app/file/**` |
| … | … | … |

**为什么这条是硬的**：12 个人最怕的就是两个人改同一处。**这条不立，前面所有设计都白做。**

### 规矩 2：统一技术底座 —— 所有人同一个仓、同一套栈

- **同一个 WorkBuddy 项目 / 同一个代码仓**，不许各建各的
- **技术栈由 M2（骨架）定死**，之后谁都不许换
- 公共样式（按钮、卡片、导航、页脚）**只在骨架里改**，各模块不许自己另写一套

> ⚠️ 这条不立，就会出现 12 个人做出 12 个长相、12 种写法的页面，最后**拼不起来**。

### 规矩 3：接口就是"路由 + 字段" —— 只有这两个约定

- **路由表定死**（`/` 首页、`/search` 检索、`/file/:id` 详情…）→ 页面之间跳转不用商量
- **字段表定死**（第四节）→ 数据怎么读写不用商量

**除了这两样，模块之间不产生任何其他依赖。** 所以任何人都能独立做完自己的那块。
