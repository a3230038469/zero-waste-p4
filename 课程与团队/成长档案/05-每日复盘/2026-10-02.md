## 六、🔴 砍范围建议（10/8 demo 只保 5 件事）

11 个页面 → **砍到 5 个**。理由：demo 的验收标准是需求方那句"**各项功能均能正常运行即可，先跑起来**"，不是功能数量。

| 保（demo 死线） | 说明 |
|---|---|
| **① 注册 / 登录** | 一页两表单，5 个字段 |
| **② 首页 + 书架** | 按四大类浏览 |
| **③ 搜索结果页** | **只搜文件名** + 筛选（类型/主题/年份）+ 排序 |
| **④ 文件详情页** | PDF 预览 + 下载 |
| **⑤ AI 问答** | WeKnora 兜底，回答带来源 |

| 砍（挪到 10/9-10/15 迭代期） | 为什么能砍 |
|---|---|
| 上传提交页 / 反馈页 | PRD 优先级本来是 P1/P2 |
| 后台·文件管理 / 审核队列 | P0 但**10/8 演示时没有用户上传内容**，管理后台没有用武之地 |
| 后台·使用统计 | 统计要真实数据才有意义，demo 当天看不出 |
| 筛选/排序升级版 | 第一版可以只做最简 |
| 双平台并行对比（R10） | 结项前的加分项，不是 demo 必需 |

> ⚠️ **砍之前必须跟老师说一句**："demo 先保 5 个核心功能，统计和后台放到 10/22 结项前补"。**不然 10/8 他看不到统计面板，会以为我们没做。**
